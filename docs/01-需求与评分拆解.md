## 5. 规格缺口与我们补的机制（务必在报告里说明）

规格逐条实现时有 **3 处会导致系统无法运转或指标失真**，实现中已补齐并写入项目记忆：

### 5.1 只有初始资金 ⇒ 首笔成交永远无法产生
规格 6.1 只配置了 `agent.*.initial.balance`。若所有 agent 一开始都只有现金、没有任何股票，
**卖出校验永远失败**，订单簿上不会出现卖盘，价格发现根本不会发生。
→ 增加配置项 `agent.<类型>.initial.holdings`（如 `agent.noise.initial.holdings=AAPL=800,GOOGL=400,TSLA=300`），
并由 `Account#seedPosition` 注入。做市/噪音 agent 必须持有底仓。

### 5.2 行情只在订单后推送 ⇒ agent 死锁
行情快照原本只在“订单受理/撤单后”广播，而 agent 的决策依赖最新快照，于是：
没人下单 → 没有行情 → 没人下单。集成测试 `SimulationIntegrationTest` 把这个死锁直接暴露出来。
→ 开盘时 `SimulationRunner#publishInitialSnapshots` 先推一次开盘行情；
并强制所有 agent 订阅 `MarketDataPublisher`（早期版本漏订阅，同样导致市场永不动）。

### 5.3 收益率基准口径
规格 4.3 定义 `Return Rate = (Equity - Initial Balance) / Initial Balance`。一旦有了初始持仓，
用“初始资金”做分母会把注入的股票成本误算成收益（实测做市 agent 会凭空得到 +339% 收益）。
→ 收益率一律以 **初始权益 = 初始资金 + 初始持仓成本** 为基准（`Account#getInitialEquity`），
并在 CSV 表头与排行榜中把该列标注为“初始权益”。`AccountTest#seededHoldingsDoNotInflateReturnRate` 为回归测试。

## 6. 与规格的其余差异（有意为之，需在报告中说明）

| 规格描述 | 我们的做法 | 理由 |
| --- | --- | --- |
| 订单簿用“两个优先队列”（4.1） | `TreeMap<价格, ArrayDeque<Order>>` | 语义等价（价格优先 + 时间优先），但撤单从 O(n) 降到 O(log n)，无需惰性删除标记 |
| 成交价“按对手方价格”（4.2） | 按**被动方**价格成交 | 与真实交易所一致：买方挂 152 撞上挂着的 149 卖单，成交价取 149，买方获得价格改善 |
| 3 层架构（3.1） | 分层保留，包结构对齐 | `gui` → `sim/app` → `engine/account/market/agent` → `io/config/model` |
