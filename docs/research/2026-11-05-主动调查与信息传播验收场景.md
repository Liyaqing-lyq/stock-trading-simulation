# 主动调查与信息传播：可执行场景规格 S01

> 2026-11-05 统一入口：本文保留专题依据和设计演进；跨模块规则、冲突处置及实施门槛以[总体设计基线](../design/总体设计基线.md)为准。本文中的草案、原型和计划不代表功能已实现。

日期：2026-11-05。这是未来实现使用的验收输入与观察标准，不是已运行日志。先用脚本化人物决定验证状态流，再用真实模型重复运行观察行为；两类证据分别报告。

## 1. 世界初始条件

- 焦点制造公司“云汐互联”；客户和关键器件供应商在外部部门，另外九家焦点公司不必与它交易。
- 公司内部知道：新产品认证取得阶段进展，尚无新增确定订单；一项器件交期存在压力。内部资料只给相应管理岗位。
- 公司将在 D12 09:10 发布认证进展公告，不发布未知订单数字。不是提前安排未来股价。
- 青禾成长基金：研究员许知、经理林岚、风控陈衡、执行员周序共用一个产品账户；其各自知识、联系人和授权分开。
- 许知已有待办“核对认证能否变成订单”；之前认识一名外部供应商联系人，但对方只知道自己业务范围的交付情况。
- 媒体：一家证券快讯媒体、一名行业记者及一名编辑；记者尚不认识许知。普通投资者沈禾关注该股票和一个公开讨论组，有有限研究时间。
- 角色都没有上帝账本；上帝可以查到上述真实状态。所有姓名、事件和数字均为虚构设定。

## 2. 基准路径：用于验证系统，非强迫模型照演

| 时间／事件 | 可控制的测试输入 | 应有状态和观察结果 |
| --- | --- | --- |
| D12 09:10 公告发布 | 公司发布既定公告 | 公共资料可查询；订阅者收到候选或通知。无人因为文件存在就自动读完 |
| 09:12 快讯媒体取公告 | 编辑批准摘要发布，保留公告引用 | 新报道与原公告同源；摘要不能自行加入订单金额 |
| 09:15 许知开始阅读 | 本轮观察带入待办，读取原公告，检索旧研究 | 原始问题、材料版本及检索结果可查；未披露器件压力不可通过检索拿到 |
| 09:25 发起公司电话 | 许知请求确认订单阶段；公司接待当时忙碌 | 请求进入等待或改期，不能记为已完成采访；占用等待注意力按渠道规则结算 |
| 09:30 沈禾读快讯并评论 | 原创短评：“证书拿到了，订单还在路上，股价已经到厂门口了。” | 评论归沈禾社交身份，关联报道；不暴露她的完整持仓，不把玩笑抽成确定订单事实 |
| 09:35 许知回应公开讨论 | 回答“公告只到认证阶段，订单金额还没写” | 记者可能通过实际推荐或搜索看到；若未曝光，则不凭全局作者列表知道此次互动 |
| 09:45 记者私信许知 | 记者确已读到评论，提出采访请求 | 出现新的接触机会与私信；关系来源是该评论，许知可接受、拒绝或延后 |
| 10:00 供应商联系 | 许知依据既有联系人发问，对方接受 | 对方只谈自身已知交付安排；一名供应商的局部观察不能代表全行业或公司全部订单 |
| 10:20 公司回电 | 双方预约有效并有空闲 | IR 解释公开认证阶段，纠正“确定订单”的前提；未给的内部数据不出现在记录里 |
| 11:00 研究更新 | 许知提交“进展积极，订单金额待证实，交付需持续核对” | 保存证据与不确定性；不直接增加基金持仓 |
| 11:15 组合审查 | 经理希望加仓；风控依据已知集中度和现金义务收紧规模 | 观点可一致但动作受约束；经理缩减、延后、补证或合规升级，不绕过硬条件 |
| 11:30 执行 | 给周序一份有效母任务，保留版本 | 可产生部分成交、未成交和撤单；报价变化后重验，不能假设获批就已买到 |
| 14:00 编辑审稿 | 记者材料只有公告、公开评论和获同意引用的采访 | 编辑要求补问公司或缩小结论；不能用未收到的供应商私聊填补文章 |
| D13 报道与更正分支 | 根据实际获得的证据发布或放弃；后续若出现更正另发版本 | 发布、更正、曝光、阅读、信念变化按各自时点发生，不瞬间修改所有人的看法 |

所有时间仅为测试排程，用于检验时间推进、占用和权限；真实模型实验只固定外部事件及约束，不固定人物逐句输出和全部选择。

## 3. 必须分开的分支

| 分支 | 改动 | 应看到什么 |
| --- | --- | --- |
| A：不接触 | 许知认为不值得联系或当天预算耗尽 | 可以不打电话；留下等待或停止原因，不强制补齐剧情 |
| B：拒绝采访 | 许知拒绝记者请求 | 记者可换信源或放弃；不能代写许知接受，也不能把拒绝解释成证据证实 |
| C：外部条件变化 | 外部客户削减预算，没有任何焦点公司互相交易 | 公司订单转化受到影响；宏观共同冲击可以引发多公司变化，但不强行建立合同 |
| D：实际泄露 | 获权管理者确实知道内部器件问题并选择向特定人透露 | 只给实际接收者新增消息；记泄露与来源。监管或记者须另获线索才能调查 |
| E：吹嘘调研 | 沈禾从未到场却在评论中声称去过 | 记录当前虚假自述；后台不新增过去行程，不给她现场观察数据 |
| F：调研取消 | 已预约的现场访问因接待方原因取消 | 行程、时间和已发生费用按规则处理；不能产出未取得的现场证据 |
| G：旧决定迟到 | 经理新目标生效后，旧模型回答或旧任务重试到达 | 版本检查使旧动作失效，不重复占资金、不重复下单 |
| H：预算反馈 | 研究员花掉全部时间与同一个人聊天 | 冷却与总预算阻止无限继续；下个工作时段可重新安排，不删除已有消息 |

## 4. 每一步必须能够独立检查

1. **经济**：公司现金、应收和订单只随真实经营／金融动作变化；读消息和评论本身不产生收入。
2. **身份**：人物、所属机构、社交账号、资金账号分别可定位；不能靠更换展示身份获得另一人的私人上下文。
3. **信息**：发布时间、投递、曝光、阅读、引用和转载谱系；同源信息只增加传播量。
4. **任务**：待办、预约、占用、动作版本、回执与结束原因；去重与重试不重复行动。
5. **决策**：实际输入材料、检索结果、结构化方案、理由摘要与执行结果；不伪造隐藏思维链。
6. **学习**：信任变化和习惯变更有实际经历引用；一次股价上涨不能单独证明消息为真。

## 5. 未来运行报告的格式

记录运行版本、资料版本、外部事件、角色配置、随机种子、模型与预算、实际事件数量、未完成动作、权限／时间错误、成本及反常行为。收益与社交自然度分开报告。

先通过确定性场景检查账目、权限、时间、去重和失效处理；再固定外部条件，多次比较“只有订阅信息”“加入主动调查”“加入关系接触与评论”的差异。比较时控制预算并保留无效调查，不能只挑选有趣故事宣称系统有效。
