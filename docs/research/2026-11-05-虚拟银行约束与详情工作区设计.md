# 虚拟银行约束与详情工作区设计

> 2026-11-05 统一入口：本文保留专题依据和设计演进；跨模块规则、冲突处置及实施门槛以[总体设计基线](../design/总体设计基线.md)为准。本文中的草案、原型和计划不代表功能已实现。

日期：2026-11-05。性质：研究与设计补充；附可丢弃的白色交互草图。未实现银行引擎、未接入 Java 或 LLM，不作为课程功能完成记录。

后续纠正与细化：用户明确十家公司不构成封闭经济，不能强行彼此合作；本稿贷款与关系图仅为可选虚构案例。开放外部部门、中国银行基础规则、媒体类型、评论和主动联系、机构交接及运行预算详见《2026-11-05-开放经济与媒体社交运行细化.md》，其最新边界优先。

## 1. 本轮确认与仍待细化的内容

用户已确认：允许虚拟银行；采用少量世界内企业直接贷款，其他客户和贷款用背景组合；接受其复杂度，但上帝视角必须清晰、透明、可查。界面保留白色及当前主布局，增加独立公司、股票、账户分析、世界关系和新闻讨论页面。

仍需设计：具体授信阈值、期限、利息与损失模型；机构权限、绩效与冲突处置；信息传播和主动行动调度。下文规则是建议，不能把尚未逐项讨论的参数视为用户确认。

## 2. 银行不是无限资金入口

银行应当是可能亏损、支付困难、失去资本并进入处置的经营实体。LLM 可以判断客户、提出授信和定价方案；是否获批、能否放款、支付成功与否、如何记账，必须通过确定性规则。

### 2.1 三种资源不能混淆

- 客户存款：客户的资产，同时是银行的负债。
- 结算准备金：银行的结算资产；与其他银行或外部结算部门支付时需要转移。
- 权益与监管资本：承担损失的基础；监管资本要按模型规则从账面权益调整得出。它们不是另一袋随时可支付的现金。

贷款通常同时形成贷款资产与客户存款，不是简单把既有储户存款转给借款人；贷款记账本身不同时创造准备金。还本可以同时减少贷款和存款。机制依据：[英格兰银行货币创造研究](https://www.bankofengland.co.uk/-/media/boe/files/quarterly-bulletin/2014/money-creation-in-the-modern-economy.pdf)，资本与流动性的区分参见[英格兰银行专题](https://www.bankofengland.co.uk/-/media/boe/files/quarterly-bulletin/2013/bank-capital-and-liquidity.pdf)。这里借鉴通用机制，不声称完整复现中国银行监管。

### 2.2 六组必须可解释的约束

| 约束 | 规则需要检查什么 | 上帝视角应看到什么 |
| --- | --- | --- |
| 资本与杠杆 | 放款后资本对风险资产的覆盖，以及总敞口；风险上升和减值后的余量 | 放款前后数值、阈值、规则版本、哪项触发拒绝 |
| 流动性与期限 | 当前可支付余额、未来到期义务、压力流出、已经落实的融资 | 到期梯形图、压力缺口、可动用资产与融资成本 |
| 集中度与关联关系 | 单户、关联集团、行业、共同偿债来源、抵押物重复使用 | 敞口条形图、关系网络、合并计算的明细 |
| 授信与提款 | 用途、偿债来源、已有债务、合同期限、抵押和审批权限 | 申请 → 调查 → 风控 → 批准额度 → 满足条件 → 提款 |
| 贷后风险与损失 | 风险迁移、到期、逾期、重组、减值、回收、核销 | 每一步原因、分录、责任主体和合同剩余义务 |
| 经营与治理 | 融资成本、信用成本、员工与运营成本、董事会风险偏好 | 利润构成、考核结果、授权变化和管理层调整 |

授信批准与实际放款分开：额度不是存款，未提款承诺也应纳入相应风险预算。放款前再次校验资源与版本，避免两个同时通过的申请共同超用额度。不得让 LLM 自报“风险很低”就绕过额度或总敞口规则。

约束类型参考 [BCBS 2024 核心原则 16–20、24](https://www.bis.org/committees/bcbs/basel-framework/standard/bcp/40/inforce/2024-04-25/published/2024-04-25)。具体数字作为本模拟明确配置的世界规则，后续如选择某一中国市场监管版本，再核对该版本，不混用不同制度的比例。

### 2.3 需要外部结算部门，但不需要立刻模拟每一家外部银行

若所有主体永远在同一家银行内转账，很多现实支付压力会消失。第一步可以设一家直接建模银行，并显式保留“背景经济／结算部门”的汇总账。

背景贷款按行业、信用档和期限分组。至少保存：期初贷款、提款、还本、利息、减值、核销和回收；每项变化都有对手账。直接建模企业不得再计入背景贷款。相同经济冲击同时作用于相关直接企业与背景组合，不能用独立噪声制造虚假的分散效果。

背景组合不必给每个客户调用 LLM，也不能直接给银行增加无来源利润。背景部门可以更换模型或参数，但账目、合同和事件的共同约定不变。

## 3. 用一笔业务检查账目闭合

以下单位均为万元；仅演示，不是实跑数据。假定无税费，设备按卖方账面价值出售，信用减值另行处理。

银行期初：结算资产 2,000 + 背景贷款 6,000 = 存款负债 7,000 + 权益 1,000。借款企业期初：银行存款 200 = 权益 200；该存款已包含在银行期初存款负债内。

| 阶段 | 银行 | 借款企业 | 外部部门 |
| --- | --- | --- | --- |
| 批准额度 1,000 | 暂不增加贷款本金和存款；另记未提款承诺及风险预算 | 暂未到账 | 无支付 |
| 放款 1,000 | 借贷款 1,000，贷客户存款 1,000 | 借银行存款 1,000，贷借款 1,000 | 无准备金转移 |
| 企业购买外部设备 600 | 借客户存款 600，贷结算资产 600 | 借设备 600，贷银行存款 600 | 收款行借结算资产、贷卖方存款各 600；卖方借存款、贷设备存货各 600；结算部门把付款行准备金负债转为收款行准备金负债 |

放款后银行：2,000 + 7,000 = 8,000 + 1,000。外部支付后银行：1,400 + 7,000 = 7,400 + 1,000。企业：600 存款 + 600 设备 = 1,000 借款 + 200 权益。

后续企业用本行存款还本 200：银行贷款与客户存款各减 200，企业借款与存款各减 200。不能再把还本当银行收入；利息应按合同另计。

现有股票交易账户的局部记账不变量保留。新增信用创造以后，不能将“全世界存款总量恒定”设为总不变量；应检查每个主体资产负债平衡、每组分录借贷相等、跨主体支付闭合，以及各类货币和债权变动的明确来源。正式实现继续使用 `BigDecimal`，草图的浮点排版不进入业务账本。

## 4. 违约、救助与失败必须有后果

信用风险恶化时先计提减值，损失通过利润影响权益；已经计提的部分后来核销时冲减准备与贷款，不能对同一损失重复扣权益。借款人已经支付给别人的存款不会随着贷款坏账自动消失。

区分合同本金债务、贷款账面本金、减值准备、净账面额、已核销仍追索额。核销不自动等于债务豁免；只有明确的重组、法律处置或债务减免事件才改变合同义务。机制参照 [IFRS 9：5.4.4、5.5.1–9、B5.5.1–5](https://www.ifrs.org/content/dam/ifrs/publications/pdf-standards/english/2022/issued/part-a/ifrs-9-financial-instruments.pdf?bypass=on)，不声称本项目完整采用 IFRS。

救助分为两类：

1. 临时流动性支持：增加结算资产，也增加对救助方的债务；有授权、额度、期限、成本、抵押与到期处置。不能将其当资本增加。
2. 资本重组／处置：明确出资方、损失承担、股权稀释和管理层调整；没有有效方案可以进入失败与处置状态。

如果世界设央行，其货币发行能力应明确建模，不能误写成“和普通银行一样必须先攒够现金”。但模拟政策必须约束何时可以使用、接受哪些抵押物、额度与成本如何形成、谁承担后果；不得成为自动补平所有亏损的按钮。参考 [FSB 处置关键属性 §5–6](https://www.fsb.org/work-of-the-fsb/market-and-institutional-resilience/post-2008-financial-crisis-reforms/effective-resolution-regimes-and-policies/key-attributes-of-effective-resolution-regimes-for-financial-institutions/)。

## 5. 上帝视角的可查链条

每个动作都沿“观察到什么 → 谁提出方案 → 谁批准或拒绝 → 哪项规则检查 → 发生哪些分录 → 后续结果”展开。至少记录：

- 业务／合同／事件标识、世界发生时间、披露时间、接收时间、规则版本。
- 当时的输入资料与权限、模型提出的结构化方案及理由摘要、人工或规则否决记录。
- 约束的前值、后值、阈值、可用余量，数据缺失与估计假设。
- 双方和结算部门分录、余额快照、执行结果、失败原因以及重试关联。
- 后续合同变更、还本付息、减值、核销、回收与救助。

上帝视角知道真实状态，银行和交易角色只能拿到自己当时可见的信息。保存可核查的决策摘要与工具记录，不要求或伪造模型隐藏思维链。“事件早于价格变化”只能说明时序关联，因果结论要通过机制和对照实验评估。

## 7. 白色工作区的页面分工

| 页面 | 首屏重点 | 下一层入口 |
| --- | --- | --- |
| 主界面 | 日 K、公司池、重大信息摘要 | 股票、公司、账户、世界与信息 |
| 股票详情 | 分时／日 K／周 K、量价、盘口与成交、事件 | 公司资料、公告／新闻／研究／讨论；日柱钻取当天分时 |
| 公司档案 | 经营链、经营指标与财务、董事会和管理层 | 合同、项目、贷款、管理决定、披露；内部事实仅向授权视角显示 |
| 账户分析 | 总权益、可用与冻结现金、收益、回撤、资产配置 | 持仓贡献、目标仓位、订单成交、费用、资金流水、机构决策 |
| 世界关系 | 选中实体周围一至两层关系，按资金／经营／组织／信息筛选 | 点实体进档案；点关系进合同或来源；显示方向、金额／敞口、有效期 |
| 信息与大事 | 按世界时间显示事件，区分事实、公告、报道、研究 | 原文、引用链、更正、传播记录及评论 |
| 人物与机构 | 身份、所属、职责、授权、目标和可见记录 | 获权账户、岗位交接、考核；个人不凭点击取得其他人私密资产 |

白底、浅分隔线、深灰绿正文，红绿主要用于涨跌且保留正负号。主界面摘要不会无限增加面板；复杂内容进入独立页。回到主界面保留标的、观察身份和世界时间。打开股票不自动切换账户，查看账户不等于接管交易。

账户图表的正式口径：初始权益包括初始持仓成本；总权益使用同一时点全组合价格，现金区分可用与冻结。工资等转入、追加资本与申赎属于外部资本流；组合股息、利息、价格变化及投资费用进入损益，不能把所有“收入”排除。扩展表现采用统一时间加权收益，有申赎产品另设份额账；确认和付款不重复计流量。具体以[总体设计基线 §6](../design/总体设计基线.md)为准。有停牌／缺价时显示估值依据与陈旧程度；缺样本显示不足，不用成本价无提示地充当市场价。

世界图必须区分供应、销售、贷款、证券持仓、任职和信息接触；持有公司证券不代表向公司直接提供同额运营资金。箭头展示合同／关系方向，不能暗示已经证明股价因果。海量节点默认聚合，展开附近关系，再按风险因子查共同敞口。

新闻评论作为独立信息对象：有作者身份、发布时间、回复关系、引用来源、可见范围、更正与删除留痕。允许角色不同意见、误读和表达策略；公开表达不等于私人信念，也不自动公开持仓。正文、评论与传播链均受回放截止点限制。上帝观察可额外看“谁接收、谁采纳、谁随后行动”，但不得把这些私人字段灌进普通评论区。

## 8. 可插拔边界

保留既有设计中的模板、实例、运行、布局分离。银行经营类型可以新增，但公司的经营账、信用合同、证券、媒体文章、人员身份、机构账户不能混为一个对象。界面复用同一观察数据，不能各自创造新的账户真值。

新增已支持类型的公司、媒体、人物或面板，应通过配置和登记完成；全新机制仍需要对应实现。复制不复制资本、历史或私密记忆；停用银行或媒体必须处理未了义务并保留历史，不能删除实体就抹除债务。具体接口沿用前一份设计稿的权限、快照和版本约定，本轮没有新建 API。

## 9. 下一步讨论顺序

原有公司池研究 §8 的顺序是“经济关系与现金流 → 管理动作、条件和披露时点 → 四岗位权限与交接”。尚没有逐章冻结的全项目路线，因此不声称机构部分已经完全定稿。

本轮建议据此推进：

1. **先完成当前世界基础**：用直接贷款、企业回款与机构持仓构成一个可以核账的小世界；明确银行约束、外部结算和救助条件。
2. **收束机构机制**：谁提出、谁批准、谁否决、冲突如何裁决、岗位如何考核、母任务如何拆单和取消。方向已确认，细节待讨论。
3. **下一块主议题是信息与媒体系统**：内部事实何时披露，媒体如何选题／采访／核实，电话与私聊如何产生，报道与评论如何传播、更正，以及各类角色的信息成本和可信度差异。
4. **然后细化 Agent 的日常行动与记忆**：唤醒、注意力预算、主动联系、检索、遗忘、偏信、习惯变化；避免每个时点所有人都行动或拥有同样上下文。
5. **最后形成可执行规格**：状态、事件、接口与错误处理，Java 分层实施、前端连接、场景验证和 PR 交付。以此前用户“先设计，后执行检查”的顺序推进。

贯穿后续设计的样例链可以是：企业回款延迟 → 银行提高风险判断 → 额度受限 → 董事会调整预算 → 公司披露 → 媒体报道 → 不同 Agent 解读与评论 → 研究员修改判断 → 经理配置 → 风控约束 → 执行拆单 → 成交与价格变化。每个箭头须指定实际触发条件，不能硬编码必然发生。

正式实现应至少验证：贷款／还本分录；跨行支付完整成功或完整拒绝；资本足够但流动性不足与相反场景；并发额度；集团敞口；减值核销不重复扣损；直接与背景组合不重复统计；救助到期与失败处置；角色不能看未披露贷款；回放不显示未来消息和评论；同一机构多个岗位始终使用同一账户与配置目标。

本轮实际界面核查记录：

- 浏览器打开白色主页及独立账户、世界关系、贷款、报道评论、股票、公司页面，逐页查看布局；账户、股票、公司和世界图均正常显示。
- 核对贷款的批准、放款、外部支付三种余额；切换角色视角后已打开的贷款详情变为无权访问。
- 核对新闻按时间排序；报道包含原始公告入口和两条有作者／时间的评论。回到前一天后报道与评论消失，回到最新恢复。
- 单股切换周 K 后 OHLC 和成交量更新；与公司页面可以相互进入。
- 从青禾研究员进入账户，权益、现金、持仓及目标与机构经理一致；切换沈禾个人身份后其他机构账户不可访问，沈禾自己的资产分析可以正常打开。
- 内联 JavaScript 语法检查通过；上述交互过程中浏览器错误日志为空。独立静态复核确认分录闭合，并指出“提款消耗结算资金”的措辞歧义，已限定为提现或跨行支付。
- 以上是合成草图的显示与交互检查，没有验证真实银行引擎、服务端权限、真实回放或完整金融计算。未运行 Java 测试、LLM 或现有仿真；未安装依赖。

课程评分表不因此标完；正式阶段仍需仓库规定的完整验证与运行记录。
