## 1. 已确认的产品要求

- Java 保留，经营记账、订单和撮合由程序执行；金额遵守现有 BigDecimal 约定。
- 首个公司样板以中际旭创的经营机制为主要参照，身份、数字、时间线与后续发展允许虚构化。八家真实公司构成后续参照库。
- 用户可见的首版包含董事会考核与调整、管理层自主经营、媒体调查与传播、交易者的信息差和关系网。
- 已公开披露对所有交易 Agent 开放主动查询；私人信息只沿实际发生的接收、交流、公开发布路径传播。
- 允许虚假消息、选择性表达、失言和有利益动机的主动泄露。必须区分真实经营事实、角色说法和角色判断。
- 代表人的 Agent 有人格、交易风格、压力、经历和关系；人格可以随长期经历变化。
- 后续讨论已确认：首版认知偏差先包含遗忘、偏信和习惯变化；不将“记错经历、自我合理化”作为首版范围。

由上述要求推导出的设计建议：公司、媒体、交易者及董事会共享基本的记忆和行动机制，各角色保留不同目标、信息范围和权限。这是本次提出的架构方案。

## 3. 原始项目实际提供了什么

| 参照 | 本次核对到的机制 | 本项目的取舍 |
|---|---|---|
| Generative Agents | 事件、想法、聊天分类；按焦点检索相关记忆；从记忆生成带证据指针的反思；日程与事件共同影响行动 | 借鉴经历、检索、反思和社交连续性；补充严格的权限、时间与事实类型边界 |
| CoffeeBench | 工具执行后反馈；模拟时间事件队列；消息、交货等唤醒；上下文过长时保留首尾并摘要中间记录 | 借鉴经营循环与调度；资金记录和关键承诺不能只留在摘要中 |
| FinMem | 新闻、季报、年报和反思分层，记忆具有衰减与重要性；训练和测试使用不同反馈 | 借鉴分层与交易反馈；改为按当前问题检索，实时角色不接收未来价格 |
| MemGPT | 有限上下文与外部记忆分离，通过工具读写、检索及管理上下文 | 借鉴按需装入与控制循环；不假定外部存储等于模型总能正确回忆 |
| LongMemEval / V2 | V1 评估更新、时间推理等能力；V2 已扩展到环境状态、工作流和失败经验 | 借鉴测试维度；补充交易时序、权限和主动行动的专用实验 |

### 3.1 Generative Agents

原始项目的 Persona 保留身份、当前状态与记忆；move 串联观察、检索、计划、反思和执行。new_retrieve 混合相关性、重要性和近期性；反思可以指向其依据的记忆节点。[Persona](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/persona.py)、[检索](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/cognitive_modules/retrieve.py)、[反思](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/cognitive_modules/reflect.py)

plan 同时处理日程和对新事件的反应，交谈有忙碌状态和冷却约束。revise_identity 在已读取实现中修改当前状态与日程，不能据函数名称认定它已实现经过验证的长期性格成长。[计划与主动交谈](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/cognitive_modules/plan.py)

需要独立验证源码：本次看到的 new_retrieve 按 last_accessed 升序排列，再将衰减幂分配给各节点，衰减系数在 0 与 1 之间时会让较旧节点得到更高的该项分数；它也没有在这条检索路径检查 expiration。这里只做了代码与公式核对，没有运行完整应用。借鉴概念不能替代验证实现。[对应源码](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/cognitive_modules/retrieve.py)

### 3.2 CoffeeBench

Agent.step_query 询问模型，step_apply 执行动作并反馈结果。Environment 按模拟时间唤醒角色，同一时间批次可以并行询问模型，再按确定顺序提交动作。账单、生产完成和消息等会触发重新观察。[Agent](https://github.com/SakanaAI/CoffeeBench/blob/main/coffeebench/agent.py)、[环境](https://github.com/SakanaAI/CoffeeBench/blob/main/coffeebench/environment.py)、[调度](https://github.com/SakanaAI/CoffeeBench/blob/main/coffeebench/event_loop.py)

ContextCompactor 保留首尾记录，摘要中段，并处理工具调用和结果不能被拆开的边界。摘要指令要求保留交易、账款和待办，但这是模型指令，不能当成数据完整性的证明。[上下文压缩](https://github.com/SakanaAI/CoffeeBench/blob/main/coffeebench/context_compactor.py)

不照搬其全部约定：其环境中上下文溢出可导致角色被标记破产；我们的技术失败必须与公司经济破产分开记录。固定提交顺序也不保证重新调用 LLM 会产生相同答案；精确回放需要保存已发生的决定和事件。

### 3.3 FinMem

使用论文链接指向的作者仓库 pipiku915/FinMem-LLM-StockTrading，未把搜索得到的第三方复刻当成原实现。源码将新闻放入 short、季报放入 mid、年报放入 long；其 __query_info_for_reflection 使用 character_string 作为各层查询，尚不等同于围绕本次交易的具体疑问检索。[agent.py](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/main/puppy/agent.py)

MarketEnvironment.step 返回次日价差，LLMAgent.step 在 Train 中使用，在 Test 中置为 None。这符合它区分离线训练与测试的思路，但我们的实时观察应从源头排除未来结果。历史案例用到的训练记忆、摘要和提示词也要遵守时间切分。[environment.py](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/main/puppy/environment.py)、[论文](https://arxiv.org/html/2311.13743v2)

记忆的重要性、衰减与跨层迁移不等于信息可信度。某条材料曾参与盈利决定，也不能证明材料为真或证明其造成盈利。[memorydb.py](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/main/puppy/memorydb.py)、[portfolio.py](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/main/puppy/portfolio.py)

### 3.4 外部记忆与评测

MemGPT 的核心启发是把模型当前能处理的上下文与更大的外部记忆分开管理。相关论文覆盖长期对话和文档任务，没有直接验证本项目所需的市场行为。[MemGPT 论文](https://arxiv.org/abs/2310.08560)

LongMemEval V1 包含信息抽取、跨会话推理、知识更新、时间推理及应当拒答的情况。2026 年的 LongMemEval-V2 已覆盖网页 Agent 的静态状态、动态状态、工作流、环境陷阱与错误前提识别；不能把当前记忆评测一概说成只有聊天回忆。[V1 官方仓库](https://github.com/xiaowu0162/LongMemEval)、[V2 论文](https://arxiv.org/abs/2605.12493)

V1 的评分还有需要注意的边界：evaluate_qa.py 对部分时间问题允许数量相差 1；知识更新问题可能接受包含正确新答案、但同时附有旧信息的回答。print_retrieval_metrics.py 计算检索分数时排除无答案样本，因此检索分数不覆盖无证据时的表现。不能将这些口径直接用于披露时点、持仓和授权的精确校验。[问答评分](https://github.com/xiaowu0162/LongMemEval/blob/main/src/evaluation/evaluate_qa.py)、[检索评分](https://github.com/xiaowu0162/LongMemEval/blob/main/src/evaluation/print_retrieval_metrics.py)

V2 更接近 Agent 工作经验，但其评测仍从预先收集的历史中取出有限上下文，再交给回答模型；论文明确指出没有直接测试执行任务时持续学习或最终任务完成。因此不能用记忆问答正确率证明市场中的无未来泄露、精确持仓、独立角色认知和合理社交。我们需要独立的模拟场景验收。[V2 论文第 4 节与附录 E.1](https://arxiv.org/html/2605.12493v1)、[V2 官方仓库](https://github.com/xiaowu0162/LongMemEval-V2)

## 4. 建议：分开保存世界记录、角色记忆和本轮上下文

本节起均为本项目的设计建议，具体参数尚未通过实验确定。

| 层次 | 内容 | 更新原则 |
|---|---|---|
| 世界与账户记录 | 经营事件、订单、成交、收付款、原始公告和消息投递 | Java 维护权威记录；角色无权改写历史 |
| 个人经历 | 该角色实际看过、听过、做过什么 | 保留时间、来源、对象和原文引用 |
| 信念与关系 | 角色认为某事可能为真、对某来源的专业信任与诚信判断 | 主观、可错、可修订；不自动升级为世界事实 |
| 目标与待办 | 待查问题、约定回电、承诺、观察条件 | 有状态、期限和结束原因；不能靠模型一直记着 |
| 人格与习惯 | 长期倾向、交易方法、研究习惯及其历史版本 | 依据经历缓慢更新，短期压力单独维护 |
| 本轮上下文 | 当前状态、触发原因、少量相关经历、未完成工作、近期交互 | 每次按当前任务重新组织，受长度预算约束 |

角色遗忘与系统删除是两回事。角色可以难以回忆某段经历，审计档案仍保留原始记录，方便解释行为和复现实验。后续讨论已确定首版先做遗忘、偏信和习惯变化；记错经历、自我合理化暂不纳入首版。这不改变原有允许角色在交流中作出错误判断、歪曲或隐瞒的设定。

公司资料与个人经历也要分开：更换管理层后，合同、债务、在建项目和获授权的公司档案继续存在；离任者的个人关系和私人信念不自动全部移交。

## 5. 一条信息怎样进入记忆

例：记者在模拟第 12 日对交易者说“客户可能增加采购”，并承认尚未看到正式订单。

系统首先保存这次实际收到的表述及来源。随后可以提取“记者声称存在增购意向，尚未确认”的记忆；角色也可以产生“我倾向认为需求正在改善”的信念。不能把两者压缩成“客户已经签下订单”。

每条材料至少能回答以下问题，具体数据结构留待施工设计：

- 事情何时发生，来源何时发布，我何时收到或实际阅读？
- 谁说的，谈的是哪个公司、人物、项目或指标？
- 这是收到的说法、自己的判断、预测、承诺还是执行结果？
- 原文在哪里；依据哪些记录；是否被更正、撤回或后续材料取代？

需要分别管理：世界中的事实、收到的文档声称的事实、角色对其内容的信念。即使公告或采访来自公司，也不能由来源名称自动保证所有陈述正确。

新材料可以更正旧材料，但不覆盖旧版本。第 15 日知道更正，不表示第 12 日已经知道。转载必须尽量保留共同的原始出处，避免把十次转述记成十个独立来源。

摘要保留不确定性、说话者、时间与证据引用。摘要无法核实的解释只能保存为角色判断；重要的数字、合同状态和资金余额从结构化记录读取。模型产生的反思不是新的外部证据。

## 6. 交易前怎样调取记忆

推荐使用两条互补路径。

第一条是程序自动带入当前必要状态：账户、持仓、挂单、有效授权、当前时间、待处理回执和到期承诺。不能因为语义检索漏掉一条记录，就让角色不知道自己仍有冻结资金。

第二条是围绕当前任务检索经历与材料。例如看到“需求改善”的报道后，Agent 可以形成三个问题：

1. 上次买入这家公司依据什么，哪些条件会推翻判断？
2. 这位记者过去的相关说法和后续核实结果是什么？
3. 公司最近有没有对订单状态作过说明？

先按当前时间、角色可访问范围和公司／人物过滤，再结合主题、关键词、语义相关性、有效版本、近期性与重要性找候选。相关性高不代表可信；被重复提及不代表更真实。

检索支持查找反证和更正。谨慎型角色可能主动使用，其他角色可能忽略；系统需要能区分“资料没有返回”“资料返回但没有阅读”“读到后选择不相信”。人格偏差与检索系统缺陷应分别可观察。

个人记忆查询只返回过去真正获得的信息；主动查询公开资料可以获得当前已公开但之前未读的材料。两者不能混成一个能够检索全世界秘密的搜索入口。

不预先断言必须使用向量数据库。先比较主体／时间／关键词检索与加入语义检索的收益，再决定存储组件；无论采用什么检索方式，权限和时间过滤都由程序执行。

## 7. 本轮上下文怎样维护

一次唤醒建议组织为：身份与职责、当前目标与必要状态、唤醒原因、相关待办、选中的历史记忆、当前交流的近期原文、可执行动作与剩余预算。

长篇材料提供摘要、出处和读取原文的能力。正在进行的对话保留必要原文；已完成的历史过程可以形成可追溯摘要。压缩前后，工具请求与对应回执、未完成承诺和决定的出处不能丢失。

固定背景无需每轮重新编写。新证据和反馈要真实进入下一轮状态，避免模型反复认为“还没有查到”。达到上下文预算时，可以结束本轮、保存待办并安排下次继续，不把技术资源不足解释成角色性格或公司破产。

外部报道、聊天和文件是角色要阅读的材料，不能赋予它们修改系统权限、读取别人的记忆或重写账本的能力。

## 8. 主动联系和搜集信息如何发生

LLM 在被调用时作选择。程序维护模拟时间、角色的日程与事件队列，按以下原因唤醒：

- 例行安排：开盘前研究、收盘复盘、董事会例会等。
- 外部事件：关注来源发布消息、收到回复、成交或风险变化。
- 自己设置的待办：次日跟进认证结果、到期回访、某条件满足后重查。
- 周期性检查：即使没有新闻，也有机会检查目标、发现信息缺口和提出新调查。

唤醒后，Agent 可以选择继续原计划、查询公开资料、检索记忆、联系某人、处理回复、交易或暂时等待。程序控制资源和权限，不替它固定每一步的研究顺序。

“主动”必须允许拒绝行动和等待。公开查询、阅读、采访与交流占用模拟时间和注意力。没有新信息时可以记录暂时查不到，设下次条件；无须无限重试。排除一个假设也算进展，不能仅以新增文件数判断。

所有电话、查询和消息首先发生在模拟世界内部。真实资料用于离线研究和校准；运行中的角色查询经过虚构化与时间筛选的世界资料，避免通过现实网络认出原型或获得未来结果。

## 9. 交流如何形成

以交易者主动询问公司为例：

1. 交易者发现具体疑问，决定是否值得花时间咨询。
2. 选择公开咨询电话、公开问答平台、已认识的联系人或预约渠道。
3. 程序登记联系请求、渠道、收件人、时间和可见范围，进入接收方队列。
4. 接收方根据职责、工作安排、已知信息与意愿决定回复、转交、延后或拒绝。
5. 双方各自读取自己的记忆，逐轮决定说什么；另一方只能得到实际发送的内容。
6. 追问、新承诺和得到的线索进入各自记录，并可能产生后续任务。

私人对话双方不能共享完整上下文，也不让一个全知模型同时代写双方决定。短消息与长谈都设置时长、轮次、冷却和结束条件；双方需要分别保留尚未完成的请求。

公开电话可被普通投资者尝试使用，关系偏好不能取消公开信息获取权。预约、是否接通及对方是否回答是另一层约束。公开问答进入公共资料库，私人沟通只投递给实际参与者，直到发生转述或公开发布。

模拟允许主动泄露或歪曲，但必须由实际说出的内容引发信息传播。未知的秘密不会为了让对话更精彩而自动提供给角色。模型编造的内容可以成为错误说法，不能反向改写经营事实。

## 10. 人格、关系和习惯怎样改变

短期情绪与压力可以快速变化；信念和对具体来源的信任随着新证据更新；长期人格变化采用更慢的复盘过程。

一次反思可以提出“以后对某类消息多查一个来源”的习惯变更，也可以提出对某个人的关系调整。长期性格变化需要关联经历、说明变化方向并保留版本；不让模型每次自由重写整个人物简介。

行为变化要允许不确定性和个体差异。连续亏损不必然变谨慎，别人失约也不必然被解释为恶意。系统记录经历和角色的解释，并检验其后续行为是否与这段变化相符。

公司董事、管理层、记者与交易者都可使用这套机制；机构授权和硬性账户限制不会因人格变化而自动失效。

## 11. 一个完整示例

以下均为待实现的虚构场景，不是已经跑出的结果。

1. 第 12 日，成长型交易者看到报道说某企业需求改善，触发关注事件。
2. 上下文自动带入其账户、挂单和“等待客户认证后再加仓”的旧待办；检索返回上次决策、记者的历史说法及当时可得公告。
3. Agent 发现报道没有区分意向与正式订单，决定查原始公告并向公司公开咨询渠道提问。
4. 公司接待角色收到请求，答复目前公开资料尚未确认正式订单，并将超出权限的问题转交管理层；相关角色分别决定后续回应。
5. 交易者把回复记为“对方这样回答”，可以选择继续等待、进一步调查或带着不确定性交易。程序不会强制所有角色作出同一个理性答案。
6. 若其决定下单，重新读取当前账户与行情，并由现有引擎校验、冻结资金和撮合。研究期间的旧报价不会被当作保证成交价。
7. 第 15 日，公司发布新的订单进展。角色在实际读到后，才更新信念并评价此前调查；原始第 12 日决策保持不变。
8. 多次类似经历后，该角色可能养成核实合同状态的习惯，并保留变化依据。

## 12. 验证设计：先证明记忆正确，再观察行为

以下是后续必须建立的实验，不是本次已经通过的检查。

| 场景 | 需要验证的结果 |
|---|---|
| 明日公告已存在于世界档案 | 今日的搜索、摘要、反思和注意力线索都不能访问它 |
| 只有甲收到私人消息 | 乙的检索不能因为语义相似而获得内容；甲后来转述则产生新的接收事件 |
| 传闻、重复转载和更正并存 | 保留源头与版本；可以区分当时说法、目前可知的更正与角色自己的看法 |
| 多次上下文压缩 | 待办、承诺、有效授权、未完成请求和引用仍能恢复；精确财务状态不依赖摘要 |
| 一段对话中途暂停并恢复 | 参与者、实际说过的话和未解决问题保持连续，不重复发送已确认消息 |
| 下单结果返回前发生重试或重启 | 不产生重复订单；未确认状态与已完成状态分开 |
| 问一个当前无从知道的问题 | 可以保持未知或主观猜测，但不得伪造历史来源 |
| 消息正确但交易亏损 | 不自动把消息源记为撒谎；区分内容准确性与交易收益 |
| 没有新外部新闻 | 角色仍能执行自己安排的调查；已无进展时能停止或等待 |
| 社交双方都很活跃 | 冷却、队列和预算防止无限互相唤醒；不丢失必要回复 |
| 长期性格变化 | 改动有经历与版本记录，后续行为可观察；不意外突破机构或账户硬约束 |
| 相同已记录运行的回放 | 事件、观察、实际检索结果、决定及提交顺序可重放；不把固定随机种子宣称为 LLM 复现保证 |

验收分两类：时间、权限、账户版本与重复执行等硬约束由程序精确检查；主动性、人格连续性和信任变化通过重复场景、行为记录与对照实验评估。主观判断允许出错，不等于系统允许突破硬约束。

内部比较至少包含：只用近期窗口、近期窗口加摘要、结构化状态加按问题检索。保持模型、输入信息、模拟时间与调用预算一致，记录证据命中、时间与权限错误、承诺遗漏、重复动作、有效调查进展、成本及行为差异。收益不是记忆系统的唯一或首要判据。

这些简化方案仅作为内部对照，用户可见的首版仍执行已经确认的董事会、人格、记忆与自主行动范围。

## 13. 下一步需要定下的内容

后续用户要求沿用本研究而非重新选方案。具体接触机会、媒体采编、通信状态、动作成本、调度预算和验收场景现已在《2026-11-05-开放经济与媒体社交运行细化.md》细化；下文“待确定”是本研究当时的阶段状态，不能据此把已明确方向重新归零。信任、遗忘和习惯变化机制保持继承。

推荐方向：共享的 Java 角色运行机制，结合结构化状态、个人经历、主观信念、待办日程、按问题检索与有限多轮行动。CoffeeBench 用于经营和调度参照，Generative Agents 用于经历与社交参照，MemGPT 和记忆评测研究用于上下文与验证参照。

进入实现前，应把本研究转成完整角色运行设计和可执行实验规格，并与公司、媒体、董事会、交易引擎的设计共同审阅。本次仅新增研究文档，未修改生产代码、配置或既有项目记忆。
