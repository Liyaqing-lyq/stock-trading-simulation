# 公司池、共同经济环境与机构内部分工研究

> 2026-11-05 统一入口：本文保留专题依据和设计演进；跨模块规则、冲突处置及实施门槛以[总体设计基线](../design/总体设计基线.md)为准。本文中的草案、原型和计划不代表功能已实现。

研究截止：2026-11-05。状态：研究与设计讨论稿，尚未转成实施规格。本轮没有修改 Java、配置、撮合规则或运行市场实验。

## 1. 已确认选择与本轮建议

用户已确认：

- 机构内部的基金经理、研究员、风控、执行交易员分别作决定。
- 先设计多个典型公司，使仓位分配、研究分工和风险比较有实际对象。
- Java 核心保留；公司、媒体、机构与个人的信息和决策需要分别建模。
- 用户可见的第一版公司要有董事会定期考核与调整机制。
- 使用现实经营机制作参考，允许世界偏离真实历史；不希望模型凭真实公司身份猜后续剧情。
- 首版认知变化聚焦遗忘、偏信和习惯变化。

本轮建议：保留用户提出的八家参考，再补长江电力与恒瑞医药，形成十家公司参考池。十是当前设计建议，不是经实验证明的最优数量；最终虚拟公司数量及与参考原型的对应方式仍待确定。

设计可以提前暴露权限、账目和因果冲突，不能保证多主体运行后没有拥挤、停滞、误判或性能问题。后续需要分别验证经营、组织决策与市场结果。

## 3. 必须保留的公司差异

共同部分包括董事会、管理层授权、资产负债与现金流、经营计划、执行进度、定期和临时披露。董事会的考核关注经营与风险结果，可调整预算、战略和管理层授权；股价是参考信息，不应成为所有公司的唯一考核目标。

各行业另有必须独立的状态：

- 银行：存款属于负债，贷款属于资产；存贷款本金不能直接当销售收入和生产费用。贷款质量变化、信用损失和存款流出要分别维护。上市银行公司与管理基金资产的机构是不同实体，不自动共享客户信息。
- 药企：维护多个研发项目的阶段、预算、已获证据与待验证问题。试验许可、试验结果、上市批准与商业放量是不同事件；授权合同的潜在总额、收到的现金和确认的收入分别记录。
- 工程：签约、履约进度、收入确认、验收与回款分别推进；不能收到新订单就立刻增加可用现金。
- 制造：需求与订单、产能与实际产量、出货与回款分开。研发与扩产有成本、时滞和失败可能。
- 消费与电力：库存陈化和来水分别具有时间与物理约束；不能因为被称作消费或公用事业，就预设低波动和稳定收益。

天娱数科 2025 年报的业务描述已包含智能营销、智慧能源和空间智能，不能固定沿用旧的游戏股标签。报告对新业务能力和前景的描述是公司披露，不等于本次独立验证了技术能力。

这些状态由 Java 维护并结算。LLM 提出目标、选择经营动作、交流与判断；不能仅凭一段文字直接改写利润、研发成果、账户现金或市场成交。

## 4. 同一个世界怎样连接这些公司

用户后续明确纠正：十家公司是焦点观察主体，不构成封闭经济；不因处于同一个公司池就强行建立合作或直接现金流。外部客户、供应商、竞争者、家庭、海外与政策环境可以独立存在。下文信用传导只是一种可选场景，不是所有公司运行的必经链。具体边界、外部部门和关系形成条件见《2026-11-05-开放经济与媒体社交运行细化.md》§2。

建议先维护有限的共同环境：需求与居民支出、融资条件、海外需求与贸易条件、原料和能源供给、水文气候、行业技术与制度事件。共同环境影响具体的数量、价格、成本、融资或执行时间，再形成经营结果和可观察证据。

例如一个虚构的信用收缩场景：客户付款推迟 → 工程企业回款变慢 → 企业申请续贷；银行结合自身资金与信用风险决定贷款条件；制造企业可能推迟资本支出；基金经理同时面对企业盈利变化和投资人赎回。最终价格由各参与者观察、判断与真实订单形成，不能从事件直接指定涨跌幅。

不同公司的相关性应主要来自共同环境、真实合同和交易者行为。可以用统计目标评估结果，但不应通过硬写每日价格波动、固定资金持股比例或强制某类股票涨停来制造结果。现有旧讨论稿的价格画像可作为待检验假设，尚未在本轮重新核准其中参数、制度和强断言。

拟议的供应、贷款、客户和竞争关系属于虚构世界设定。本轮没有核实上述十家真实企业彼此的合同关系，不应把虚构关系当成真实关系引用。

公司对外销售、工资、采购、融资和投资者收入支出都要记录对手方或明确的外部部门。不能用无来源的余额增减维持繁荣；涉及银行信用创造时，也要维护相应资产负债与结算关系，而不是错误要求所有货币余额永远不变。

## 5. 机构四个岗位的独立决定

以下是本项目拟定权限，不声称所有真实基金都采用完全相同组织结构。

| 角色 | 独立决定 | 必须交付 | 权限边界 |
| --- | --- | --- | --- |
| 研究员 | 研究哪家公司、询问谁、采用什么证据、何时修正观点 | 证据来源、经营假设、情景估计、置信程度、反证和有效期限 | 不能用研究报告直接修改基金账户或替管理层创造事实 |
| 基金经理 | 在合同和授权内分配股票与现金仓位，取舍研究建议 | 目标仓位、理由、时间尺度、失效条件和可接受成本 | 不能绕过账户约束及有效风控限制；目标不等于已持仓 |
| 风控 | 检查共同风险、集中度、流动性和赎回义务，按授权限制或暂停任务 | 触发证据、受影响任务、有效期限和解除条件 | 风险判断可有误；程序硬限制始终有效，不能被对话覆盖 |
| 执行交易员 | 在母任务授权内选择节奏、拆单、挂单、撤单与重新报价 | 已成交、待执行、成本、偏离原因及异常反馈 | 不能擅自改变投资方向或超额建仓；无法成交要反馈 |

一个基金产品使用同一份资产账目。四个岗位持有自己的上下文、经验和社交关系，通过明确的报告、消息和会议共享内容；同一公司下的多个基金产品也不能自动混用资金。

仓位计算至少区分：当前成交持仓、未完成订单和已冻结资产、目标仓位、已知现金义务。反复收到同一研究意见不能反复创建完整买入任务。目标调整需关联已有任务，处理撤单与成交竞态，避免旧单和新单叠加后超配。

例：研究员认为某制造企业订单改善；基金经理希望加仓；风控发现现有组合已经高度依赖同一海外需求，并收到赎回通知；经理可调整增仓幅度和资金来源，交易员再执行已获授权的任务。双方观点和实际动作不同，不需要改写任何人的人格来解释。

初始可以让一名研究员覆盖多家公司，用关注清单和时间预算取舍。是否增加行业研究员由后续覆盖需求决定，不预设每家公司都配满一套机构人员。

## 6. 运行节奏、记忆与可观察性

- 公司经营、董事会考核、研究更新、组合决策和订单执行采用各自合适的模拟时间尺度。
- 研究员由待办、定期覆盖、重要消息或问题追问唤醒；经理由组合变化、申赎、研究更新或定期评估唤醒；交易员由订单任务与行情变化唤醒。
- Java 持续执行账目、订单、权限和明确的风险规则；不要求每次行情变化都调用全部 LLM。
- 机构内部的观点也保留来源和时间；同一传闻被多人转述不能自动增加独立证据数量。共同文档的修订不自动覆盖每个角色的旧记忆。
- 上帝视角显示真实公司状态、信息传播、角色分歧、目标与实际仓位、风控限制和执行任务。个人视角只展示有权接触的信息。

具体唤醒频率、延迟、token 预算、账户结构和模拟时间尺度仍需定稿；本轮没有给出未经测量的承载人数或运行速度承诺。

## 7. 隐藏原型与偏离历史

仅替换名字仍可能让模型根据业务组合和事件顺序识别原型。建议进一步重组客户结构、地域、规模、产品线、资本结构、管理层历史和时间顺序，让多个参考机制组成虚构公司；是否采用这种组合方式尚待确认。

现实原型映射保留在设计资料中，不进入交易者或管理层的运行上下文。世界可以沿不同管理选择和环境路径发展，不能预装一条真实历史未来供角色检索。

仍不能承诺模型完全无法推断行业或参考来源。后续可进行盲测：只提供角色实际可见资料，检查原型识别率，并测试不同猜测是否不当影响行为。识别出行业本身不是错误，利用未在模拟中发生的现实后续事件才需要重点检测。

## 8. 后续设计与验证问题

下一步宜先画出虚构公司的经济关系与现金流，再为每种机制列出管理动作、执行条件、形成的事实及披露时点，随后细化四个机构岗位的权限和任务交接。界面依照这些真实状态呈现。

2026-11-05 后续确认：用户允许虚构银行，接受“少量可追踪的直接贷款关系 + 背景贷款和客户组合”，要求约束明确、上帝视角逻辑与交互透明可查。授信、结算、损失和救助规则的设计补充见《2026-11-05-虚拟银行约束与详情工作区设计.md》；具体参数仍待细化，尚未实现银行引擎。

实施后至少要用如下场景验证，而非只检查模型能否输出文字：

1. 同一环境冲击在不同经营结构下产生可解释的收入、成本与现金变化。
2. 看好公司但赎回压力较大时，研究结论、仓位决定与成交行为能够分离。
3. 风控暂停任务后，新的子单受阻，既有挂单与可能已发生的成交得到正确处理。
4. 目标仓位连续调整、订单部分成交时，不会重复下达完整任务或重复占用资金。
5. 研发或合同里程碑失败时，未来预期变化，但不会凭空扣除从未收到的现金。
6. 相同输入下记录真实动作便于回放；LLM 调用不因固定随机种子就自动保证逐字重现。
