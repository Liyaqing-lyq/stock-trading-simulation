# 项目设计复审与争议处置

日期：2026-11-05。任务：重新检查整体设计，补足不足和会造成不同实现结果的规则。

结论：方向可以继续推进，但原来分散的设计还不能直接当成一套一致的实施合同。本轮形成[总体设计基线 v0.1](../design/总体设计基线.md)，修正旧稿中的明确错误，并补充跨模块规则。以下“已修订”仅指文档；新增世界能力仍待代码、测试和运行实验验证。

## 1. 覆盖与方法

读取项目协作规则、项目记忆、七份专题设计，检查旧《A股长期交易与多Agent扩展设计》、课程评分拆解、接口和开发流程的相关段落。对经济/账目、信息/运行、界面/交付三条线做独立交叉审查，再统一修订。没有将此前已经明确的开放经济、利润与回款分离、复制不复制资本等重复列成缺失。

新增外部核查：上交所 2026 年交易规则发布通知、正文相关条款和暂缓实施附件；GIPS 手册总回报、现金流和红利计提段落；英格兰银行货币创造说明。其他原型公司、媒体与多 Agent 项目的资料沿用专题已有来源，未声称本轮重读全部原文或实际运行其项目。

未运行仿真、LLM、Java 测试或真实银行业务；未联系任何真实公司/个人。没有变更生产 Java、运行配置或既有项目记忆。文档中的算账例子是验收夹具，不是实验结果。

## 2. 实质问题与处理

“高”表示会直接影响资金正确性、信息可见性、实验结论或课程交付；“中”表示会造成状态不可解释或实现路线争议。不是漏洞评分，也不声称代码已经出现相应故障。

## 3. 本轮推荐默认与仍需验证的取舍

| 问题 | 推荐默认 | 代价/边界 |
| --- | --- | --- |
| 世界规模 | 十类公司研究保留，先制造公司完整竖切，再工程/银行，再其他模板 | 先闭合共同机制，不用十个空壳作为完成数量 |
| 银行系统 | 简化托管映射＋少量直接贷款＋受约束背景组合 | 可解释、可对账；不是完整清算系统或监管合规库 |
| 运行时间 | 实验时间屏障＋真实调用失败独立记录 | 可减少网络速度影响，但等待模型会减慢实际运行 |
| 正常交流与泄露 | 保留已允许的泄露/误导；硬隔离越权读取和写账 | 可以研究现实不完美行为，不能让模型技术幻觉冒充内幕 |
| 记忆与考核 | 可见反馈慢速更新，实验者评分隔离 | 不保证所有人永不趋同，需要实验检验 |
| 公司治理 | 固定章程、事前指标、定期考核与异常升级 | 表决、任免和权限必须真实产生后果，不能只画会议记录 |
| 崩溃恢复 | 本地单进程可靠提交和检查点，记录回放 | 实现成本高于 CSV；单靠随机种子不足 |
| 插件 | 类型明确的接口与版本，安全点升级 | 同类新增方便；新机制仍需代码和迁移 |
| 人工接管 | 看过全知信息后默认进入标记的新分支 | 原实验可保留，不能把有内幕的人类订单混作纯 Agent 结果 |

模型规模、行为参数、银行完整档案和正式图表底座仍需试验/实现核验；不是让实现者自行创造默认事实。缺少运行必需配置时启动校验拒绝，不能静默开启残缺机制。
