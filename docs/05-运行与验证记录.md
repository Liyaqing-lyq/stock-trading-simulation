## 5. 本次开发中发现并修复的真实缺陷（含回归测试）

| # | 缺陷 | 现象 | 根因 | 修复与回归 |
| --- | --- | --- | --- | --- |
| 1 | agent 未订阅行情总线 | 模拟跑完 0 笔成交 | `SimulationRunner` 只把 CSV 记录器挂到 `MarketDataPublisher`，agent 收不到行情 → 永不下单 | 构造完成后统一订阅所有 `MarketDataListener` agent；由 `SimulationIntegrationTest` 守住 |
| 2 | 开盘无行情快照 | 市场静默不动 | 快照只在订单受理后推送，形成“没人下单→没行情→没人下单”死锁 | `start()` 先推一次开盘行情 |
| 3 | 收益率基准错误 | 做市 agent 凭空 +339% 收益 | 只按“初始资金”做分母，未计入注入的初始持仓成本 | 新增 `getInitialEquity()` 作为收益率基准；回归测试 `seededHoldingsDoNotInflateReturnRate` |
| 4 | **agent 只挂单从不撤单，冻结额度永不释放** | **运行约 40 秒后成交量骤降，50–69 秒完全为 0，盘口只剩挂单** | 限价单提交即冻结资金/持仓，只有成交或撤单才释放。agent 从不撤单 → 冻结额单调累积耗尽 → 撞到 `NoiseAgent` 唯一的 `continue` 分支 → 全场停止下单 | `AbstractTradingAgent` 加存活挂单登记 + 撤单 API + `ensureCapacityFor()` 额度自恢复；三个 agent 每轮报价刷新。见下方 §5.1，回归测试 `MarketContinuityTest` |
| 5 | **`MomentumAgent` 限价定在最新价，永远不成交** | 该 agent 静默地一笔都不成交，却持续冻结额度 | 最新价必落在买一卖一之间，价格等于最新价的限价买单低于卖一、卖单高于买一 → 永远排队不成交 | 报价改用对手价（买用卖一、卖用买一），以被动方价格成交并获得价格改善 |

前两个缺陷都是**集成测试**（真起线程）才暴露的：单元测试全绿时市场依然一动不动。
这也是本项目坚持保留端到端集成测试的原因。

### 5.2 回归测试 `MarketContinuityTest` 的有效性验证

新增的回归测试从**行为**层面锁定这条链路，不依赖具体实现：

1. 运行期间必须出现**主动撤单**（旧实现撤单数恒为 0）；
2. **模拟末段窗口内仍有成交**（旧实现在该窗口已停摆）；
3. 存活挂单总量**有界**。

**并且验证过它确实能抓到 bug**：把修复点临时改回旧行为（`trimQuotes`/`cancelAllOpenOrders` 返回 0、
`ensureCapacityFor` 恒返回 true、`MomentumAgent` 报价退回最新价），测试失败并给出：

```
org.opentest4j.AssertionFailedError: 运行末段（2026-09-28T10:32:29.935420990 之后）必须仍有成交，
否则市场已停摆；实际全部 59 笔成交都集中在运行前段
```

恢复修复后 `mvn test` 全绿。**一个从没失败过的回归测试等于没有测试**，所以这一步必须做。

### 5.3 尚未解决：缺少涨跌幅约束导致价格随机漫游

3 分钟长测同时暴露一个**未修复**的问题：没有涨跌停限制时价格会漂移到不合理的幅度，
实测 AAPL 已到 **-12.36%**、GOOGL 到 **+14.85%**——A 股主板一个交易日内不可能出现这种幅度。

结论：**涨跌幅校验必须与换标的同期落地**（设计文档 6.2 的 P1），
否则长期跑出来的“价格序列”没有可比性。此处如实记录，不假装已解决。
