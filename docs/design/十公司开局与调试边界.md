# 十公司开局与调试边界

当前目标是让同一个世界可以真实运行、定位拒绝、恢复并分支对照。它是内部调试版，程序验收、真实模型行为和现实校准分开记录；十家公司齐全不代表总体基线全部验收完成。最新部署与证据以[当前实施](../CURRENT_IMPLEMENTATION.md)和[运行记录](../05-运行与验证记录.md)为准。

下文的公司资金、来水期限、授信范围和退出条件仅适用于早期 `industry-baseline-v1`。修订后的预注册全员实验使用 `web-ten-company-autonomy-v23`。该档有三个个人证券账户，九户发行人各有授信记录，来水路径为 1080 日，原购电合同为 360 日。已逐户验证的退出与旧约包括资源公司停业后收回应收、数字公司退款以及三家制造公司停止签新单后继续履约。工程发行人的分红、个人市价单、各公司的受控账本和自然运行进度见[当前实施看板](../CURRENT_IMPLEMENTATION.md)与[自然运行评价方案](../experiments/2026-11-27-十公司自然运行评价.md)。

## 明确的新开局

启动模式 `world-baseline`，档案 `industry-baseline-v1`，日志 `world-industry-baseline-v1.journal`。旧档保持旧规则，不自动增加公司或改变初始财产。

| 公司 | 标识 | 可调试的区别 |
| --- | --- | --- |
| 技术型制造 | mfg-tech | 技术代际、认证与产品 |
| 结构型制造 | mfg-struct | 材料条件与产品结构 |
| 通用型制造 | mfg-versa | 多产品与产能分配 |
| 工程 | eng-a | 合同、履约、验收和实际收付 |
| 银行 | northbank | 存款、支付、贷款与资本/流动性分别核对 |
| 药企 | pharma | 分阶段研发与项目证据 |
| 资源 | resources | 开采、外售、内部转运、发电、扩产和爬坡 |
| 水电 | hydro | 来水、库容、放水、发电与检修 |
| 数字服务 | digital-company | 试点、验证、客户准入、合同交付和退款 |
| 陈酿 | aged-company | 原料、生产、成熟、寄售、终端售出和回款 |

原单制造 `cufe` 不再是发行人，但保留资产管理机构与四岗；第二工程公司 `eng-b` 不在此新开局。初始股份由既有份额分配给两个交易账户，未扩大总发行量。两个投资账户各有实验初始现金 10000 元；外部客户、供应商、电网和创始人均有独立有限账户，不暗中补足。

没有预置经理任命和经营预算。经理候选人不等于现任经理；董事任命与预算生效后，人物才取得对应工具。固定成本、陈酿需求和水电物理结算仍随世界时间发生，无人管理不是停止负债和成本的理由。

## 建议的调试顺序

1. 先在上帝视图检查开局、公司账、待办和五组 Key 的场景配置。默认模型场景关闭，浏览和推进确定性时间不会自行启用模型。
2. 先选择一家公司的治理场景，检查董事看到的开局材料，完成真实任命和预算。经理页面只显示其任职公司。董事否决、预算不足、任期届满应保留拒绝记录。
3. 用人物经营页提交动作，再推进到动作完成时点；“已排程”不是“已完成”。同时核对现金、银行存款、订单冻结、库存、应收应付与完整权益。
4. 使用历史/分支入口保留干净开局，人工接管的运行明确作为受干预实验；在分支中启用少量人物和有限调用预算。先检查真实输入、工具回执、用量和失败原因，再增加人数。
5. 保存并重启，确认原记录、现金、库存和待办一致；重启后重新显式开始模型轮，不能把恢复日志当成重新请求模型。

## 早期开局 industry-baseline-v1 的边界

- 数字服务的“商用准入”是冻结的实验客户技术许可，不代表真实董事会商业化决议；新增试验和服务投入仍受实际董事预算约束。新资本注入未开放。
- 陈酿未付款原料采购到到货期末失效，不凭空入库；固定费用不足形成应付。终端销售受实际货量、报价和有限买方现金约束，成熟不保证有人购买。
- 水电只冻结 360 个实验日的来水和购电合同，超过范围需要新情景，不能外推成无限来水。水电、数字、陈酿等经营数值均为 EXP，尚未完成真实公司参数校准。
- 此开局的银行信用配置主要覆盖工程借款主体。新增公司有真实存款/付款能力，不等于都已具备完整授信产品。
- 资源退出与新资本注入尚未作为可执行生命周期开放。十公司接线不能代替总体基线中的全部生命周期验收。
- 确定性测试使用的脚本模型回执，不是实际大模型行为证据。群体趋同、信息传播、遗忘与习惯、压力下无成交，以及现实经验有效性仍须单独实验并报告失败。

## 验证入口

十公司专项：`BaselineIndustryWorldTest`、`BaselineIndustryWebHttpTest`、`BaselineIndustryRecoveryTest`，包含无经理跨期、数字跨期交付/退款、陈酿完整资金链、三个真实 JVM 恢复、父子隔离与篡改拒绝。资金适配、各行业权限和既有档案兼容还有独立检查；具体数量与退出码只引用当次运行记录。

最终交付仍执行 `scripts/verify.sh --with-gui`、CSV 复算、JavaDoc、评分映射和带 `[AI-Generated]` 的 PR。AI 独审不代替至少一名人工成员的 review。
