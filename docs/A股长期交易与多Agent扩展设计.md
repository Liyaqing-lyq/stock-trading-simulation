# 从美股玩具市场，到能跑「长期」的 A 股市场

## 零、先搬开拦路的那块石头：仿真会「僵死」

### 0.1 现象

系统连续跑一段时间后，**成交量掉到零，盘口上却堆着一片挂单**——不是没人下单，是单永远不成交了。

实测（`simulation.tick.interval.ms=1000`，跑 90 秒，**修复前**）：

| 时间窗口 | 下单笔数 | 成交笔数 | 成交量 |
| --- | --- | --- | --- |
| 0–9 秒 | 84 | 55 | 4 483 股 |
| 10–19 秒 | 51 | 38 | 2 168 股 |
| 20–29 秒 | 32 | 32 | 1 364 股 |
| 30–39 秒 | 37 | 32 | 1 515 股 |
| 40–49 秒 | 9 | 5 | 139 股 |
| **50–59 秒** | **0** | **0** | **0 股** |
| **60–69 秒** | **0** | **0** | **0 股** |
| 70–79 秒 | 0 | 0 | 0 股 |
| 80–89 秒 | 0 | 0 | 0 股 |

注意第 50 秒之后**下单笔数也掉到 0**——这不只是"没成交"，是 agent 干脆不下单了。这一点是定位根因的关键线索。

### 0.2 根因：挂单只增不减，冻结的资金与持仓永不释放

`Account` 的规定是：限价买单提交时**冻结** `限价 × 数量` 的现金，限价卖单提交时**冻结**相应持仓；
只有**成交**或**撤单**才会释放。而原来的三个 agent（`NoiseAgent`、`MomentumAgent`、
`LlmTradingAgent`）**只挂单，从不撤单**。于是：

1. 每个 tick 挂出的新单都冻结一笔额度，已挂的单永久占着不放；
2. 冻结额单调累积，很快耗尽「可用现金」与「可卖持仓」；
3. `NoiseAgent` 在两者都不够时执行 `continue`（跳过本标的下单）——这是它唯一的跳过路径；
4. `MomentumAgent` 的预算按"可用现金的 20%"计算，可用现金趋近 0 后单量也趋近 0；
5. 全场 agent 都走到这一步后，没人再提交新单，盘口只剩一堆永不成交的陈旧挂单，成交量归零。

代码层面的因果是封闭的：`NoiseAgent.onTick()` 里唯一的 `continue` 就是那个额度检查，
而实测中下单笔数同时归零，只能是所有 agent 在所有标的上都撞到了这个 `continue`。

**还有第二个独立缺陷：`MomentumAgent` 根本不可能成交。**
最新价是"上一笔成交价"，撮合完成后它必然落在买一与卖一之间（订单簿不交叉）。
而原实现把**限价定在最新价**：买单低于卖一、卖单高于买一，两张单都只会静静排队，永远不成交。
换言之，这个 agent 一期都没真正交易过，却持续冻结额度——它是个"死" agent。

### 0.3 修复：给 agent 加上「挂单生命周期管理」

真实市场的参与者不是只挂不撤的。做市商持续**撤单改价**（quote refresh），
限价单也有时效——这才是"额度可以循环使用"的原因。修复就照这个来：

| 修复点 | 位置 | 做法 |
| --- | --- | --- |
| 挂单跟踪 | `AbstractTradingAgent` | 记录本 agent 所有未终结订单（id / 标的 / 方向 / 顺序） |
| 撤单能力 | `AbstractTradingAgent` | 新增 `cancelOpenOrders(条件)` / `cancelAllOpenOrders()` / `cancelOldest(n)` |
| 报价刷新 | 三个 agent | 每轮先撤掉过期/超量的旧报价，再按新行情重新报价 |
| **额度自恢复** | `AbstractTradingAgent.ensureCapacityFor()` | 额度不足时**先撤自己最旧的挂单腾额度**，而不是直接放弃下单；撤无可撤才返回 false |
| 主动成交 | `MomentumAgent` | 报价改用**对手价**（买用卖一、卖用买一），保证能真正成交 |

`MomentumAgent` 改为以对手价报价后，它的买单会立刻吃掉卖一、以被动方价格成交
（买方获得价格改善，符合撮合引擎既有约定），价格发现因此真正开始工作。

### 0.4 修复效果与回归测试

同一配置跑 90 秒（**修复后**）：

| 时间窗口 | 下单笔数 | 成交笔数 | 成交量 |
| --- | --- | --- | --- |
| 0–9 秒 | 133 | 57 | 4 282 股 |
| 20–29 秒 | 144 | 62 | 4 605 股 |
| 40–49 秒 | 136 | 55 | 3 982 股 |
| **70–79 秒** | **133** | **29** | **2 037 股** |
| **80–89 秒** | **131** | **28** | **1 905 股** |

对比最末两个窗口：修复前 0 笔 0 股，修复后 28–29 笔约 1 900 股。成交量不再随时间衰减。

新增回归测试 `MarketContinuityTest`，从**行为**层面锁住这条链路（不依赖具体实现）：

1. 运行期间必须出现**主动撤单**（旧实现撤单数恒为 0）；
2. **模拟末段窗口内仍有成交**（旧实现在该窗口已停摆）；
3. 存活挂单总量**有界**，不随时间无界增长。

**这个测试是验证过"能抓到 bug"的**：把修复点临时改回旧行为后，它确实失败并报出
「末段必须仍有成交……实际全部 59 笔成交都集中在运行前段」；恢复修复后通过。

> 结论：**在讨论"加多少 agent"之前，先让市场能一直成交。** 这一步做完，
> 后面所有关于 agent 类型、交易方式、长期交易的设计才有意义——否则加多少 agent 都是往一个死掉的市场里加。

## 一、先看清现状：差距在哪

### 1.1 现有系统 vs A 股现实

| 维度 | 当前实现 | A 股现实 | 影响 |
| --- | --- | --- | --- |
| 标的 | AAPL / GOOGL / TSLA | 沪深两市 A 股（6 位代码） | 制度完全不同，美股无涨跌停、T+0、无印花税 |
| 时间跨度 | 单次会话 300 秒 | 一个交易日 4 小时，长期是 250 日/年 × N 年 | 没有"日"的概念，谈不上长期 |
| 撮合方式 | 连续竞价（价格-时间优先） | 开盘集合竞价 + 连续竞价 + 收盘集合竞价 | 收盘价的形成机制缺失 |
| 涨跌幅 | 无限制 | 主板 ±10%、创业板/科创板 ±20%、北交所 ±30% | 涨停买不到、跌停卖不掉，这个现象不存在 |
| 交割 | 即时（买入即可卖） | **T+1**，当日买入当日不可卖 | 隔夜风险不存在，日回转不可能 |
| 交易单位 | 任意股数 | 买入 100 股整数倍，卖出可零股 | 小额账户的约束缺失 |
| 交易成本 | 0 | 佣金 + 过户费 + 印花税，往返约 0.10% | 长期收益被系统性高估 |
| 企业行为 | 无 | 分红、送转除权、停牌、退市、回购 | 长期收益的主要来源缺失 |
| 参与者 | 3 类（人类 / AI / 噪音） | 散户 99.7% 的数量 + 机构 + 游资 + 产业资本 | 市场价格的形成机制过于单一 |
| 委托类型 | 限价、市价（一种） | 沪深各 2 种 / 5 种市价申报 + 大宗 + 盘后 | 机构拆单、做市报价无法表达 |

### 1.2 六处结构性差距（后面所有设计都从这六条推出来）

1. **没有"交易日"这个对象。** 一切长期指标（日频净值、年化、最大回撤、换手率）都以"日"为单位，系统必须先有 `TradingDay` 和日终清算。
2. **没有价格约束。** A 股最独特的现象——涨停板封单、跌停板流动性枯竭、连板炒作——全部来自涨跌幅限制。没有它，游资类 agent 无处存在。
3. **没有 T+1。** 它把 A 股的所有策略逼向"至少持有一个晚上"，隔夜跳空风险成为定价的一部分。
4. **没有交易成本。** 这一点被严重低估，见第二章 2.5。
5. **只有 3 类 agent，且决策逻辑高度同质。** 现有 `MomentumAgent` 和 `LlmTradingAgent` 本质都是"看最新价做趋势"，市场缺少对手盘结构。
6. **没有企业行为与信息流。** 长期回报的来源不是日内价差，而是分红、盈利增长和估值变化——这些现在是零。

## 二、A 股到底怎么运行：制度层

> 本章所有规则以《上海证券交易所交易规则（2026 年修订）》为准（2026 年 7 月 6 日起施行），深交所、北交所同步修订。参考来源见第八章。

### 2.1 一个交易日的骨架

| 时段 | 阶段 | 关键规则 |
| --- | --- | --- |
| 09:15 – 09:25 | 开盘集合竞价 | 可申报可撤单；09:20–09:25 不可撤单 |
| 09:25 | 开盘价产生 | 按 **最大成交量** 原则撮合确定开盘价 |
| 09:30 – 11:30 | 连续竞价（上午） | 价格优先、时间优先；申报价需在有效竞价范围内 |
| 11:30 – 13:00 | 午间休市 | 可申报，不可撤单 |
| 13:00 – 14:57 | 连续竞价（下午） | 同上午 |
| 14:57 – 15:00 | 收盘集合竞价 | 仅可提交限价申报，**不可撤单**，统一撮合产生收盘价 |
| 15:05 – 15:30 | 盘后固定价格交易 | 2026-07-06 起由科创板扩展至 **全部 A 股及 ETF**，按当日收盘价成交 |

沪市盘后固定价格交易申报时间为 09:30–11:30、13:00–15:30；深市 A 股、北证 A 股为 09:15–11:30、13:00–15:30。

**对仿真的含义**：你们现在只有一个"连续竞价"撮合器。要贴近 A 股，至少需要 **两个撮合算法**——连续竞价（已有）和集合竞价（最大成交量原则，需要新增），以及一个「交易时段状态机」来控制哪些委托在哪个时段被接受。

### 2.2 两种撮合方式必须都存在

**连续竞价**（你们已实现）：新订单到达即与对手方最优价撮合，成交价取被动方（挂在簿上那一方）价格。这条你们的口径和真实交易所一致，可以保留。

**集合竞价**（需新增）：不即时成交，而是把所有申报汇总后，寻找使**成交量最大**的价格作为成交价；同价申报全部成交，剩余按价格优先、时间优先排队。

```
集合竞价定价算法（简化版）：
1. 收集买单（按价降序）与卖单（按价升序）
2. 对每个候选价格 p，计算可成交量 = min(Σ买单(qty | price ≥ p), Σ卖单(qty | price ≤ p))
3. 取使 可成交量 最大的 p 作为成交价；并列时取使未成交余量最小的
4. 成交价 = p，所有 price ≥ p 的买单与 price ≤ p 的卖单按时间优先配对
```

收盘集合竞价的引入有现实意义：2026 年新规明确沪市基金收盘阶段由连续竞价改为集合竞价，理由是减少尾盘拉升砸盘、让收盘价更能反映全天多空均衡。

### 2.3 涨跌幅与有效竞价范围

| 板块 | 代码前缀 | 涨跌幅限制 | 备注 |
| --- | --- | --- | --- |
| 沪市主板 | 600 / 601 / 603 / 605 | ±10% | 2026-07-06 起 ST、*ST 也统一为 ±10%（原 ±5%） |
| 深市主板 | 000 / 001 / 002 / 003 | ±10% | 同上 |
| 创业板 | 300 / 301 | ±20% | 2026-07-06 起引入做市商制度 |
| 科创板 | 688 | ±20% | 已有做市商制度 |
| 北交所 | 8xx / 4xx | ±30% | 风险警示股票当日累计买入不超过 20 万股 |

除涨跌幅外，连续竞价阶段还有**有效竞价范围**约束：申报价格不能过度偏离最近成交价（申报价格笼子），超出范围的申报会被交易主机拒绝或暂存。仿真中至少要实现"价格被拒绝"这一条，否则 agent 可以无成本地报出任意价格。

> 实现提示：涨跌幅限制应该在**撮合引擎入口**做校验并返回明确的拒绝原因（`PRICE_OUT_OF_LIMIT`），而不是在 agent 里裁剪——因为在真实市场里，**是交易所拒绝你，不是你自己不下单**。这个区别对研究"涨停买不到"很关键。

### 2.4 交易单位、最小变动价位与 T+1

- **最小变动价位**：A 股 0.01 元（分），所有委托价必须是 0.01 的整数倍。你们已经用 `BigDecimal` scale=2，天然满足。
- **申报单位**：买入必须是 100 股（1 手）的整数倍；卖出时若持仓不足 100 股，须**一次性全额卖出**（零股卖出）。这条会让小额账户和分红送股后的持仓（可能不是整手）产生真实约束。
- **T+1**：当日买入的股票，当日不能卖出；当日卖出的股票，资金当日可用于继续买入（可用于买入），但**提现要等到 T+1**。仿真中至少要实现"可卖数量 = 昨日收盘持仓"，即持仓要区分 `settled`（可卖）与 `unsettled`（当日买入，不可卖）。

顺带说明：机构大资金常用的"T0 回转"不是违反 T+1，而是**用底仓做日内价差**——先卖后买同样的数量，用底仓腾出的额度完成日内交易。仿真里如果有底仓概念，这种策略会自然涌现，不需要特殊实现。

### 2.5 交易成本：长期交易最大的敌人

A 股交易成本由三部分组成（费率以常见水平计）：

| 费用 | 收取方 | 费率 | 双边/单边 |
| --- | --- | --- | --- |
| 佣金 | 券商 | 不超过成交金额 3‰，实际常见 万 2.5 – 万 3，**单笔最低 5 元** | 双边 |
| 过户费 | 中国结算 | 成交金额的 0.01‰（0.001%） | 双边 |
| 印花税 | 国家税收 | 成交金额的 1‰，**减半征收 0.5‰（0.05%）** | **仅卖出方** |

按佣金万 2.5 计算：

```
买入单边 = 0.025%（佣金）+ 0.001%（过户费）           = 0.0260%
卖出单边 = 0.025%（佣金）+ 0.001%（过户费）+ 0.05%（印花税）= 0.0760%
一次完整往返（买+卖）                                  = 0.1020%
```

**这个数字意味着什么**：如果一个账户每天都完成一次「全仓卖出再买入」，一年按 242 个交易日计算：

```
净值留存 = (1 − 0.00102) ^ 242 = 0.7812   →  年损耗 21.88%
（若佣金为万 3，往返 0.112%，留存 0.7625，年损耗 23.75%）
```

也就是说，**在什么都没做的情况下，每日全仓换手就能吃掉超过 20% 的年收益**。散户"长期跑不赢指数"最硬的算术根源就在这里，而不是选股能力。

对小资金更残酷：成交额 1000 元时，单笔最低 5 元佣金 = 实际费率 0.50%，买卖往返合计 10.52 元 = **1.052%**；而成交额 10000 元时，万 2.5 佣金单边仅 2.50 元（未触及最低），往返回到 0.102%。**同一个策略，小资金的实际成本是大资金的十倍。**

**对仿真的含义**：必须在 `Account` 的结算路径里扣费，并且要**分开记账**（佣金/过户费/印花税分别统计），否则无法回答"哪类 agent 的交易成本最重"这个有价值的问题。另外，最低 5 元佣金这一条会让"高频小单"策略在仿真里自然被淘汰——这正是我们想观察的现象。

### 2.6 分红、送转与除权除息

长期回报的核心来源在 A 股尤其明显。2025 年中国结算代发 A 股现金红利：沪市 1633 家合计 5966.07 亿元，深市 1910 家合计 2991.99 亿元，**合计约 8958 亿元**；2025 年末沪深 A 股总市值 107.84 万亿元，整体现金分红率约 0.83%（不同板块、不同公司差异极大，银行/公用事业类可达 4%–6%）。

仿真要处理的机制：

- **现金分红**：股权登记日收盘持有 → 除息日股价下调分红金额 → 红利到账（通常延后数个交易日）。**分红不是凭空多出来的钱，除息会使股价等额下跌**，这一点做错会让长期收益率虚高。
- **送股 / 转增 / 拆股**：持仓数量按比例增加，股价按比例下调，总市值不变。
- **配股**：需股东掏钱认购，不参与则被摊薄。
- **复权**：要计算长期收益率，必须使用**后复权**价（把分红送转还原进历史价格）。见 3.5。

### 2.7 停牌、风险警示与退市

- **停牌**：重大事项、盘中异常波动都可能触发。停牌期间订单簿关闭，Agent 持有的仓位无法调整——这是长期持有最真实的尾部风险之一。
- **风险警示（ST / *ST）**：公司被实施风险警示后代码前加 ST；2026-07-06 起主板 ST 涨跌幅由 ±5% 放宽至 ±10%，与主板普通股统一（创业板/科创板 ST 为 ±20%，北交所为 ±30%）。
- **退市**：A 股退市常态化后，长期持有单一标的的尾部风险显著上升。仿真中至少要有"标的可被移除"的机制。

**机制设计建议**：把「停牌 / 复牌 / 涨跌幅调整 / 退市」当作**交易所 agent 发出的市场事件**，而不是硬编码在引擎里。这样 4.5 节说的"交易所也做成 agent"就有了落地理由。

| 盘后固定价格交易扩容 | 适用范围由科创板/创业板股票扩展至**全部 A 股和 ETF**，15:05–15:30，按收盘价成交 | 需要新增一个交易时段和一种订单类型 |
| 主板 ST 涨跌幅放宽 | ST、*ST 由 ±5% 调整为 ±10% | 风险警示股票的波动特征改变 |
| 沪市基金收盘机制 | 由连续竞价改为收盘集合竞价 | 基金类标的需集合竞价撮合 |
| 创业板引入做市商 | 创业板股票可实行做市商机制 | 为 4.2 节的做市商 agent 提供了制度依据 |
| 创业板大宗交易确认 | 协议大宗交易确认时间由盘后统一确认改为盘中实时确认 | 大宗交易的影响更即时 |

## 三、「长期交易」在 A 股是什么意思

### 3.1 长期不是"买很久"，而是三层时间尺度

这是全篇最重要的一节。**"长期"是一个多层概念，只加长仿真时长不会自动得到长期市场。**

| 层 | 时间尺度 | 内容 | 现状 |
| --- | --- | --- | --- |
| **结算层** | 1 天 | T+1 交割、日终清算、权益快照、日频净值 | 完全缺失 |
| **持仓层** | 数日 ~ 数年 | 隔夜跳空、分红再投资、调仓、复利 | 完全缺失 |
| **考核层** | 数月 ~ 数年 | 不同资金的排名周期与强制行为（赎回、排名压力、考核赎回） | 完全缺失 |

**考核层是最容易被忽略、但决定了市场行为的一层。** 同一个市场里跑着不同时间尺度的人：

- 公募基金按**季度**排名，排名靠后会面临赎回，赎回必须卖出股票 → 形成"下跌—赎回—再下跌"的负反馈；
- 保险、社保按 **3–5 年**考核，下跌时反而加仓；
- 散户按**天**考核（看盈亏数字），容易追涨杀跌；
- 被动指数基金只在**指数调整**时换仓，平时几乎不交易。

**长期市场的真实结构，是这些不同时间尺度资金互相博弈的结果。** 如果所有 agent 都用同一个决策周期，无论跑多久都只是"加长版的日内市场"。

> 设计推论：**agent 的决策周期必须显式建模，并且与它的考核周期绑定。** 现有系统里所有 agent 都用 `simulation.tick.interval.ms` 同一个间隔，这需要改。

### 3.2 A 股参与者结构：谁在市场上

| 玩家 | 数量占比 | 持股市值占比 | 决策周期 | 典型行为 |
| --- | --- | --- | --- | --- |
| 个人投资者 | > 99.7% | 约 30%（2023Q2 降至 30% 以下，十余年最低） | 数天 | 换手率高、跟风炒作、处置效应 |
| 境内专业机构 | < 0.24% | 约 15.4%（2023H1） | 数月至数年 | 公募看排名，保险/社保看长期 |
| 其中"国家队"（社保/养老/年金/证金/汇金） | — | 约 4.5%（2023Q3，持股市值 3.14 万亿） | 3–5 年 | 逆周期、稳定市场 |
| 外资（北向 + QFII） | — | 约 4.9%（2023 年 6 月末） | 数月至数年 | 价值风格、基本面驱动 |
| 产业资本（非金融上市公司、一般法人） | — | **约 43.2%**，长期最高 | 数年 | 回购、增持、减持 |

**关键数据**：境内机构持股比例持续超过 70% 的公司，2013 年以来平均年化收益率接近 13%；个人投资者比例持续超过 70% 的公司，同期平均年化收益率低于 3%。这不是因果结论，但它诚实地说明：**机构持股结构不同的公司，长期价格行为是两种物种。**

A 股投资者数量（中国结算口径，2025 年末）：投资者总数 2.5067 亿，2025 年新增 1386.95 万（其中自然人 1382.84 万）；开立信用证券账户的投资者 784.48 万。上交所口径 2025 年末投资者数 2.64 亿户、股票账户数 3.99 亿户（两口径不同，勿混用）。

### 3.3 长期收益从哪来

```
长期总收益 ≈ 股息率 + 盈利增长率 + 估值变化率
```

对照 A 股：整体股息率不到 1%（但结构分化极大，高股息板块 4%–6%），长期指数收益主要由盈利增长和估值波动贡献——**而估值波动的方差远大于前两项之和**，这就是 A 股"长期持有体验差"的原因。

**这决定了 agent 设计的分工**：

- 价值/配置型 agent 赚的是 **股息 + 盈利增长**（需要基本面数据）；
- 交易型 agent 赚的是**估值波动**（只需要行情）；
- 指数型 agent 两者都赚，但**必须处理分红再投资**，否则长期净值会被系统性低估。

### 3.4 长期才有意义的指标体系

现有的 `PerformanceTracker`（收益率、胜率、最大回撤）是日内口径。长期需要补充：

| 指标 | 口径 | 为什么长期才有意义 |
| --- | --- | --- |
| 年化收益率 | 基于日频净值，按 242 交易日折算 | 短期收益率噪音极大，无统计意义 |
| 年化波动率 | 日收益标准差 × √242 | 同上 |
| 夏普比率 / Sortino | 超额收益 / 总风险 / 下行风险 | 需要足够长的样本 |
| 最大回撤 + 回撤持续期 | 权益曲线峰值到谷值的幅度与天数 | 持续期才反映真实痛苦程度 |
| 换手率 | 成交金额 / 平均权益 | 直接挂钩交易成本 |
| 持仓周期 | 加权平均持有天数 | 区分交易型与配置型资金 |
| 相对基准的 Alpha / Beta / 跟踪误差 | 对沪深 300 或中证 500 回归 | 只有多日数据才可回归 |
| 分红再投资贡献度 | 股息收益 / 总收益 | 长期最重要的分解项之一 |

### 3.5 复权：不处理这个，长期收益率全是错的

A 股标的分红送转频繁，**不复权的价格序列在长期是断裂的**。三种口径要分清：

- **不复权**：真实成交价，可用来撮合、算持仓市值、算当日涨跌幅；
- **前复权**：以最新价为基准调整历史价，用于技术指标和回测（历史价格会随新的分红不断变化）；
- **后复权**：以历史价为基准调整后续价，**用于计算长期收益率**（乘性、稳定、不因新分红而变）。

**系统设计建议**：撮合与撮合账一律用不复权价；绩效统计保留一条后复权序列专门算长期收益。如果这两条混用，agent 的"长期年化"会凭空高出好几个百分点。这和你们已经踩过的坑（收益率分母用初始资金 vs 初始权益）是同一类错误——**口径错误比 bug 更隐蔽**。

## 四、多 Agent 设计：从 3 类扩展到 18 类

### 4.1 用四个问题区分 agent

现在 `AgentType` 只有 `HUMAN / AI / NOISE` 三个值，区分维度是"谁写的"。真实市场的区分维度应该是这四个：

1. **信息集**：它能看到什么？（只有行情 / 行情 + 盘口 / 行情 + 财报 / 行情 + 新闻 / 有内幕信息）
2. **决策频率**：多久决策一次？（毫秒 / 分钟 / 日 / 周 / 季）
3. **目标函数**：它在优化什么？（绝对收益 / 相对排名 / 跟踪误差 / 库存中性 / 负债匹配）
4. **下单方式**：它怎么表达意图？（限价挂单 / 主动吃单 / 算法拆单 / 集合竞价申报 / 大宗）

**同一个"散户"，在这四个维度上可以分成完全不同的四类 agent。** 这是 A 股仿真最关键的设计洞察——`NOISE` 这一个类型之所以不够，不是数量问题，是它把"随机挂单"和"追涨杀跌"和"长期定投"混成了一种东西。

建议的 `AgentType` 扩展（可按需取舍）：

```java
public enum AgentType {
    HUMAN,            // 人类 broker（保留）
    AI,               // LLM 交易员（保留）
    MARKET_MAKER,     // 做市商
    HFT,              // 高频 / 盘口不平衡
    NOISE,            // 零信息噪音（保留，作为流动性背景）
    RETAIL_LONGTERM,  // 长期散户 / 定投
    RETAIL_MOMENTUM,  // 追涨杀跌散户
    RETAIL_LOTTERY,   // 彩票型偏好（炒小炒差）
    HOT_MONEY,        // 游资 / 涨停敢死队
    MANIPULATOR,      // 虚假申报等操纵行为（用于监管研究）
    MUTUAL_FUND,      // 公募基金（相对排名 + 申赎驱动）
    QUANT_FUND,       // 量化私募（多因子 / 统计套利）
    NORTHBOUND,       // 外资（基本面驱动，信息滞后）
    PENSION_INSURANCE,// 保险 / 社保 / 养老金（超长期）
    INDEX_FUND,       // 被动指数（只在调仓时交易）
    VALUE_INVESTOR,   // 价值投资者（估值 + 分红驱动）
    INDUSTRIAL_CAPITAL,// 产业资本（减持 / 增持 / 回购）
    NEWS_AGENT        // 信息 / 事件驱动
}
```

### 4.2 分层 agent 清单

#### A 层：流动性提供（决定价格能不能连续变化）

| Agent | 信息集 | 频率 | 目标 | 下单方式 | 参考来源 |
| --- | --- | --- | --- | --- | --- |
| `MarketMakerAgent` 做市商 | 盘口深度 | 秒级 | 库存中性 + 价差收益 | 双边限价（本方最优价格委托） | 深交所创业板 2026 起引入做市商 |
| `HftAgent` 高频 | 盘口不平衡 | 毫秒级 | 短期价差 | 主动吃单 + 极速撤单 | ABIDES 的网络延迟模型 |
| `NoiseAgent` 噪音（已有） | 仅最新价 | 秒级 | 无 | 随机限价 | ABIDES 的 Zero Intelligence 基线 |

**做市商的价值**：它把买卖价差显式变成一个有意识的选择，而不是随机挂单的副产品。`NoiseAgent` 提供的是"有流动性"，`MarketMakerAgent` 提供的是"**有定价的流动性**"——价差会随库存和波动自适应调整。这是两个不同的东西。

#### B 层：散户（A 股的特色，必须细分）

| Agent | 关键行为特征 | 决策频率 | 与现实的对应 |
| --- | --- | --- | --- |
| `RetailLongTermAgent` | 按月/按周固定金额买入，几乎不卖，不看盘 | 周 / 月 | 基金定投人群 |
| `RetailMomentumAgent` | 看到涨就追、看到跌就割；**处置效应**（盈利了急着卖，亏损了死扛） | 日 | 大多数活跃散户 |
| `RetailLotteryAgent` | 偏好低价股、ST 股、次新股、高波动股；愿意为"暴富概率"付溢价 | 日 | 炒小炒差 |
| `RetailAnchorAgent` | 以**成本价**为锚，亏损越大越要补仓摊薄 | 日 / 周 | 补仓摊薄成本 |

**这四个 agent 的行为差异，才是 A 股高波动、高换手、尖峰厚尾的微观来源。** 尤其 `RetailMomentumAgent` 的处置效应（行为金融学中最稳健的实证发现之一）——它不是"随机"，而是**有结构的、可预测的非理性**。这类 agent 比增加更多的噪声明更接近真实。

#### C 层：游资（A 股独有的现象，依赖涨跌停机制）

| Agent | 行为 |
| --- | --- |
| `HotMoneyAgent` 涨停敢死队 | 在涨停价挂巨量买单**封板**；次日若封板失败立刻砸盘出货。这个行为**只在有涨跌停的市场里存在**，是引入涨跌幅限制后的自然产物 |
| `ManipulatorAgent` 操纵者 | 虚假申报（挂大单制造假深度后撤销）、拉抬出货。ABIDES 论文明确指出这类行为的意图无法从历史数据中识别，只能靠仿真研究 |

#### D 层：机构配置（长期资金的主体）

| Agent | 考核周期 | 行为 |
| --- | --- | --- |
| `MutualFundAgent` 公募 | 季度排名 | 排名压力 → 追热门板块；遭遇赎回 → **被动卖出**（负反馈放大器） |
| `PensionInsuranceAgent` 保险/社保 | 3–5 年 | 逆周期；下跌时加仓；偏好高股息大盘蓝筹；换手极低 |
| `NorthboundAgent` 外资 | 数月–数年 | 基本面驱动、价值风格；**信息滞后**（北向资金实时数据自 2024 年 8 月起不再盘中披露，仿真的 agent 也应只看到滞后数据） |
| `QuantFundAgent` 量化 | 周–月 | 多因子选股、统计套利；标的分散、换手较高 |
| `IndexFundAgent` 被动指数 | 无（跟踪误差） | 只在成分股调整时交易，平时几乎不动 |

**`PensionInsuranceAgent` 和 `IndexFundAgent` 是"长期交易"最纯粹的代表**：它们的存在就是为了不交易。如果系统里只有短线 agent，价格会持续剧烈波动，永远看不到"长期"该有的样子。

#### E 层：价值与基本面

| Agent | 信息集 | 行为 |
| --- | --- | --- |
| `ValueInvestorAgent` | 行情 + 财报（PE / PB / ROE / 股息率） | 估值低于内在价值时买入，回归时卖出；持有数月到数年 |
| `NewsAgent` / 事件驱动 | 公告、新闻、舆情 | 对信息做反应，含反应过度与反应不足两种模式（可接 LLM） |

#### F 层：产业资本（A 股最大的持股方）

| Agent | 行为 |
| --- | --- |
| `InsiderAgent` 大股东/董监高 | 限售解禁后减持（长期供给压力的主要来源）；也有增持护盘 |
| `BuybackAgent` 上市公司回购 | 市值管理型买入，通常有价格上限，长期托底 |

产业资本持股比例约 43%、长期是 A 股最高的一类，**但在现有系统里完全没有对应物**。忽略它会让"长期供需结构"整个失真。

### 4.3 优先级：分三批做，别一次上 18 类

**第一批（必做，是"A 股化"的地基）**

1. `MarketMakerAgent`——替代/升级 `NoiseAgent`，提供有定价的流动性
2. `RetailMomentumAgent`——A 股波动的主要来源，且实现简单（趋势 + 处置效应）
3. `ValueInvestorAgent`——长期资金的代表，需要引入第一个基本面数据源
4. `PensionInsuranceAgent` 或 `IndexFundAgent` 二选一——提供"几乎不交易"的长期锚

**第二批（体现 A 股特色）**

5. `HotMoneyAgent`——依赖涨跌停机制，做完成涨跌幅限制后立刻加
6. `MutualFundAgent`——引入"赎回导致被动卖出"的负反馈
7. `RetailLongTermAgent` 与 `RetailLotteryAgent`——补齐散户光谱两端
8. `InsiderAgent`——产业资本减持，给长期市场提供供给压力

**第三批（研究性，看时间）**

9. `HftAgent`——需要有计算/网络延迟模型才有意义
10. `ManipulatorAgent`——监管研究，ABIDES 明确指出的仿真优势场景
11. `NorthboundAgent`、`QuantFundAgent`、`NewsAgent`

### 4.4 关键机制：计算延迟与信息不对称

ABIDES 论文里最值得借鉴的两条设计，恰好能解决你们未来的两个问题：

**（1）计算延迟（computation delay）。** 每个 agent 有一个"思考耗时"，它会被加到该 agent 的当前时间和所有发出消息的延迟上。这样**"想得多就下单慢、下单慢就来不及"**变成系统的一条物理规律，而不是靠 agent 自觉。

对你们的意义：现在 `LlmTradingAgent` 每次决策要调 LLM，真实耗时几秒；而规则型 agent 是微秒级。**在真实市场里，LLM 交易员的成本就是"慢"。** 把 LLM 调用的真实耗时注入到它的下单延迟里，这个对比才诚实——否则你会得到"LLM 又快又准"的假结论。

**（2）每个 agent 独立随机种子。** ABIDES 用一个全局种子只生成各 agent 的子种子，好处是：**做 A/B 实验时，改动一个 agent 不会扰动其他 agent 的随机序列。** 换句话说，观察到的差异来自策略改变，而不是随机数错位。

对你们的意义：现在的 `NoiseAgent` 用 `20260924L + i` 固定种子，这个思路是对的，但要做**策略对比实验**（人类 vs AI、不同 agent 类型），必须把这条规则制度化——否则"AI 比动量策略好"可能只是随机数运气。

### 4.5 交易所也应该是一个 agent

当前架构里"交易所"的职责散落在 `MatchingEngine` 里（撮合 + 校验 + 收盘撤单）。ABIDES 把交易所做成一个**普通 agent**，它不享有特权，也通过消息和其他 agent 通信。好处：

- **停牌 / 复牌 / 涨跌幅调整 / 退市** 变成交易所主动发出的事件，而不是硬编码；
- **监管干预**（问询函、盘中异常波动核查、限制交易）有了自然的归属；
- 收盘集合竞价、盘后固定价格交易成为交易所的"服务"，而不是散落的 if-else。

建议新增 `ExchangeAgent`，把现在的时段控制、涨跌停校验、停牌管理收拢进去。**这是第三阶段的架构改造，不用现在做，但数据结构要留出口子。**

### 4.6 按标的类型匹配 agent 结构（先定这个，再谈数量）

4.1–4.2 给出的是**全市场**的 agent 清单。但对本项目来说，更有用的问法是：
**「档案 C 和档案 D 需要哪些 agent 才能涌现出那种价格行为？」**
——因为这两个档案是你要补的，也最难做。

| Agent 类型 | A | B | C | D |
| --- | --- | --- | --- | --- |
| 做市/报价（`NoiseAgent`） | 必需 | 必需 | 必需 | 必需（高峰会被打穿） |
| 长期配置机构 | **主导** | 参与 | 少量 | 无 |
| 公募/私募 | 参与 | **主导** | **主导** | 无 |
| 趋势/动量（`MomentumAgent`） | 少量 | 参与 | **主导之一** | 参与 |
| 游资（打板/接力） | 无 | 参与 | **主导之一** | **主导** |
| 散户 | 参与（定投） | 参与 | 参与（跟风） | **主导之一**（跟风接力） |
| 价值/基本面 | **主导之一** | 参与 | 少量 | 无（与基本面脱钩正是其特征） |
| 产业资本 | 参与 | 参与 | 参与（减持压力） | 无 |
| 信息事件 | 少量 | 参与 | **必需** | **必需**（题材催化） |

> 表中 A/B/C/D 即 6.1 节的四个标的档案：A 大盘价值型、B 成长制造型、C 高景气科技型、D 投机高标型。

**结论——要补的 agent 按优先级只有 4 类：**

1. **信息事件 agent**：档案 C 和 D 的价格都是由事件驱动的，没有它就没有"主线行情"和"题材炒作"。做成可注入的事件流（订单/业绩预告/政策/公告），而不是让 agent 凭空猜。
2. **游资 agent**：档案 D 的主导者，也是档案 C 的重要参与者。行为核心是**涨停价排队打板 → 次日看竞价决定接力或出逃 → 情绪退潮时炸板**；没有涨跌停制度它无法存在，所以它必须在 P1 之后做。
3. **景气轮动机构 agent**：档案 C 的另一半。按季/按月调仓，行为上是**分批建仓 + 数据触发加仓 + 回撤止损**，与游资的短线博弈形成"机构 vs 游资"的张力。
4. **基本面锚 agent**：档案 A 的主导者，给整个市场提供长期估值锚，也是检验复权/分红口径的最佳载体。

**先别做的**：把 4.2 的 18 类一次性铺开。对当前四个标的来说，
上面 4 类 + 已有的 3 类就是完整结构；再加只会稀释行为差异，还会把"哪个 agent 造成了什么现象"变得无法归因。

> 判断标准很简单：**每加一类 agent，都要能说清它负责涌现哪个可观测的统计特征**（对应 6.1 的容差表）。
> 说不清就先不加。

## 五、交易方式设计：从 2 种委托扩展到 12 种

### 5.1 委托类型

现状：`OrderType` 只有 `LIMIT` 和 `MARKET` 两种。A 股实际支持的委托方式：

| 委托类型 | 沪深 | 语义 | 建议 |
| --- | --- | --- | --- |
| 限价委托 | 沪深 | 指定价格，未成交部分挂簿 | 已有 |
| 对手方最优价格委托 | 沪（科创板）/ 深 | 以对手方最优价（买一/卖一）为限价立即成交，剩余以该价挂簿 | 新增 |
| 本方最优价格委托 | 沪（科创板）/ 深 | 以本方最优价挂簿（不主动成交） | 新增，做市商专用 |
| 最优五档即时成交剩余撤销 | 沪 / 深 | 只能吃掉对手方最优五档，剩余立即撤销 | 新增 |
| 最优五档即时成交剩余转限价 | 沪 / 深 | 同上，剩余转为该价限价单 | 新增 |
| 即时成交剩余撤销（FAK） | 深 | 能成交多少成交多少，剩余立即撤销 | 新增，语义等价于现有"市价单"的深市口径 |
| 全额成交或撤销（FOK） | 深 | 必须一次性全部成交，否则整单撤销 | 新增 |

**注意一个现有实现的口径问题**：你们现在的 `MARKET` 是"扫簿直到没对手盘，剩余撤销"——这实际上是深市的 **FAK**，不是"沪市最优五档"。更名并拆成多个类型，能让行为更贴近真实。

### 5.2 执行算法（机构拆单）

大资金不可能一次下单，必须拆。这是"长期交易"里最容易被漏掉的一环——**机构的行为模式是"慢慢买"，不是"一次买完"**。

| 算法 | 逻辑 | 对应现实 |
| --- | --- | --- |
| TWAP | 把大单平均拆到一段时间内的多个小单 | 基础机构拆单 |
| VWAP | 按历史成交量分布拆单，成交量大的时段多下 | 主流机构算法 |
| 冰山单 | 只露出小部分，成交后自动补单 | 隐藏真实意图 |
| POV（按比例参与） | 按市场成交量的固定比例参与 | 不冲击市场 |

**实现建议**：不要把这些塞进 `OrderType`，而是做成 `ExecutionAlgorithm` 接口——它接收一个"目标持仓变化"，内部产生一连串 `OrderRequest`。这样 agent 的策略（想做什么）和执行（怎么做）就解耦了，和你们现有的"agent 只依赖 `OrderGateway`"分层一致。

### 5.3 条件单与散户行为

散户实际用的委托方式很不一样，它们不是交易所的委托类型，而是**券商的客户端功能**：

- 止盈单 / 止损单：价格触发后市价或限价平仓
- 触价单（Stop）：突破某价后转为限价单
- 跟踪止损（Trailing Stop）：回撤固定比例即卖出
- 定期定投：固定日期固定金额买入（对应 `RetailLongTermAgent`）

**建议**：这些做成 **agent 内部的策略状态**，不要进引擎。理由：它们在真实世界里由券商系统持有、由券商代客户下单——放错层次会让引擎承担不该有的业务逻辑。但**必须实现**，因为散户的止损行为是"下跌加速"的重要来源（大量止损单在同一价位聚集，一旦触发就形成连锁抛压）。

### 5.4 非连续竞价通道

| 通道 | 规则 | 仿真价值 |
| --- | --- | --- |
| 集合竞价申报 | 09:15–09:25 开盘、14:57–15:00 收盘，收盘阶段不可撤单 | 研究开盘/收盘价的形成 |
| 盘后固定价格交易 | 15:05–15:30，按当日收盘价成交 | 2026 新规扩容至全部 A 股；机构大额调仓不冲击盘中价 |
| 大宗交易 | 协议成交，通常相对市价折价，有最低数量门槛 | 大股东减持、机构换仓的主要通道，**影响长期供需** |

**大宗交易对"长期"尤其重要**：产业资本减持往往不走竞价市场，而是通过大宗交易折价转让。如果只实现竞价撮合，会低估产业资本对长期价格的压力。

---

### 5.5 按标的类型匹配交易方式（哪些是"必需"，哪些是"锦上添花"）

交易方式也不是越多越好。判断依据只有一条：
**某个档案缺了它，那种价格行为就涌现不出来。**

| 交易方式 | A 价值型 | B 成长型 | C 高景气 | D 投机高标 | 缺了会怎样 |
| --- | --- | --- | --- | --- | --- |
| 限价单（已有） | 必需 | 必需 | 必需 | 必需 | 市场基础 |
| 市价单（已有简化版） | 用 | 用 | 用 | 必需 | 追涨杀跌无法表达 |
| **深市五种市价委托** | 少用 | 用 | 用 | **必需** | 打板、炸板、封单排队全都表达不了 |
| **集合竞价申报** | 用 | 用 | 用 | **必需** | 开盘抢筹与封单的起点缺失，连板链条断掉 |
| **TWAP / VWAP（机构拆单）** | **必需** | 用 | 用 | 无 | 机构建仓退化成一次性冲击，价格曲线严重失真 |
| 冰山单 | 用 | 用 | 用 | 无 | 大额挂单冲击过大 |
| **条件单（止损/止盈）** | 少用 | 用 | 用 | **必需** | 情绪退潮时的踩踏出不来 |
| 盘后固定价格交易 | 用 | 用 | 用 | 无 | 制度完整性 |
| 大宗交易 | 少用 | 用 | 用 | 无 | 产业资本减持路径缺失 |
| 融资融券 / 转融券 | 用 | 用 | 用 | 用 | 缺做空压力（A 股融券受限，可放后期） |

**按档案归纳，真正"必需"的只有四条：**

- **档案 A**：TWAP/VWAP 拆分 + 分红除权的正确记账 —— 否则"长期持有"的收益曲线是错的；
- **档案 C**：事件驱动的调仓 + 趋势跟随 —— 否则没有主线行情；
- **档案 D**：**深市五种市价委托 + 集合竞价申报 + 条件单** —— 这三样缺任何一个，连板与打板都做不出来；
- 全体：限价 + 市价。

> 换句话说：**P5 的清单不用全做。先把档案 D 需要的那三样做出来**，
> 因为涨跌停制度、市价委托、集合竞价是相互咬合的一整套——只做涨跌停而不做市价委托，
> 结果会是"涨停了但没人能买"，与真实的"涨停封单排队"完全不同。

## 六、落到本项目：建议的实施路线

### 6.1 标的：复刻「类型 + 交易方式」，不复刻名字

按你的要求：**不要照搬真实股票的名字，把它的类型和交易方式复刻出来就行。**
所以标的不用"贵州茅台""中际旭创"这类真名，而是用**一组画像参数**去定义一个「标的类型」，
代码用可识别的虚构代号；现实原型只在标定参数时作参考，不进模拟。

> 如果你们之后想拿真实行情做对照实验，把代码换回真实代码即可，**画像参数完全不变**。

**四个标的档案（覆盖 4 种截然不同的市场生态）**

| 档案 | 代号 | 类型原型 | 板块 / 涨跌幅 | 日波动率 | 日换手率 | 机构/游资/散户 |
| --- | --- | --- | --- | --- | --- | --- |
| **A** | `V001` | 大盘价值型（消费龙头） | 沪市主板 ±10% | 1.0–1.5% | 0.2–0.4% | 70% / 5% / 25% |
| **B** | `G001` | 成长制造型（新能源产业链） | 创业板 ±20% | 2.5–3.5% | 1.5–2.5% | 55% / 25% / 20% |
| **C** | `T001` | 高景气科技型（光模块 / 算力主线） | 创业板 ±20% | 4–6% | 4–8% | 45% / 35% / 20% |
| **D** | `S001` | 投机高标型（低位低价炒作标的） | 深市主板 ±10% | 6–9% | 10–25% | 5% / 60% / 35% |

**每个档案的「交易方式」特征**（这才是"复刻类型"的核心——价格形态是交易方式涌现出来的结果）

| 档案 | 价格行为 | 主导交易方式 | 对模拟系统的要求 |
| --- | --- | --- | --- |
| **A** | 低波动、慢趋势、回撤浅；分红率 2–3% | 机构 **VWAP 分批建仓**；散户定投；几乎无打板 | 复权与分红口径正确；长周期考核指标 |
| **B** | 中期趋势明显，单日 ±10% 常见，回撤深 | 机构**景气轮动调仓**、趋势加仓与止损；游资做日内波段 | ±20% 制度；做市商制度（2026 起创业板引入） |
| **C** | **主线行情**：放量突破、连续大阳、急涨急跌；机构与游资同场博弈；换手极高 | 机构分批建仓 + **景气数据触发加仓**；游资跟风打板、隔日接力；趋势交易者突破买入 | **信息事件驱动**（订单 / 业绩 / 技术迭代）；机构与游资混合结构；趋势跟随 agent |
| **D** | **连板 / 打板**：涨停封单堆积、开板即崩；题材驱动、与基本面脱钩；有"启动→加速→分歧→退潮"的情绪周期 | 游资**涨停价排队打板**、隔日接力、炸板出逃；散户追涨杀跌 | **涨跌停限制**（否则连板无从产生）；市价委托；情绪状态机；集合竞价抢筹 |

**只有 D 能验证涨跌停制度**——涨停买不到、跌停卖不掉、封单排队，这些现象全在它身上。
**只有 C 能验证"机构 + 游资混合"结构**——单一类型的 agent 永远涌现不出主线行情。
**A 和 B 提供长期基准与制度对照**。四个档案合起来，才构成一个"像 A 股"的市场。

**怎么判断"复刻得像不像"**：不能靠肉眼说像。对每个档案，用模拟产出与真实原型的
**统计特征**对齐，误差落在容差内才算通过：

| 检验项 | 口径 | 建议容差 |
| --- | --- | --- |
| 日收益率标准差 | 全样本日频 | ±20% |
| 日换手率均值 | 全样本日均 | ±30% |
| 收益率分布峰度 | 日频，衡量"肥尾" | 定性：峰度 &gt; 3 |
| 涨跌停发生频率 | 触及涨跌停的交易日占比 | ±30%（档案 D 尤其关键） |
| 自相关 / 波动聚集 | 收益率平方的 ACF 前 5 阶 | 定性：存在波动聚集 |
| 最大单日回撤 | 全样本 | ±25% |

> 这一节的验收方式直接接上 6.4：**加一个统计检验测试**，把上述统计量与目标值比较；
> 参数调到容差内才允许合并。否则"像 A 股"永远只是个说法。

**为什么不建议继续用 `AAPL / GOOGL / TSLA`**：它们没有涨跌停、没有 T+1、没有印花税，
用它们验证 A 股规则等于自欺，而且它们全是低换手大盘股，**连"投机高标"这一整类市场生态都表达不了**。
改标的是成本最低、收益最直接的一步。

> 数据来源提示：仿真初期不需要真实历史数据，可以像现在一样用参考价 + agent 行为涌现价格。
> 但**"复刻得像不像"必须靠统计量说话**，所以目标统计量要来自真实原型的真实数据——
> 这是需要引入真实日线数据的唯一理由（含分红送转的复权因子），属于第二阶段。

### 6.4 验收标准（沿用你们现有的尺度，不放松）

按 `AGENTS.md` 的要求，每个阶段的完成证据必须是：

1. `bash scripts/verify.sh --with-gui` 全绿（测试套件 + 从 CSV 的黑盒复算 + 界面真实启动）；
2. 新增规则必须有**针对性的回归测试**，特别是**拒绝路径**（涨停买不到、T+1 卖不掉、费用算错）；
3. 真实运行输出追加到 `docs/05-运行与验证记录.md`；
4. 评分表状态同步更新到 `docs/01-需求与评分拆解.md`。

**额外建议**：为"长期"加一条守恒式断言——**在没有任何交易的情况下，若剔除分红与费用影响，账户总权益应保持不变**。这条断言能一次性抓住复权口径、分红除权、费用记账三类错误。

## 七、从 6 个 agent 到 5 万个：规模、架构与种群设计

第四、五章给出的是**骨架**（18 类 agent、12 种交易方式），第六章给出的是**标的与顺序**。
本章回答剩下的那个问题：**每一类各放多少个、跑在什么架构上、怎么证明它更像真实市场。**

先把结论放在前面：

> **「增加 agent 和策略数量」方向是对的，但它是 P3，不是 P0。**
> 它解决不了本次的僵死；而僵死如果不修，5 万个 agent 会让情况更糟——
> 不是更慢地坏，而是**更快地坏**。

### 7.1 先把因果摆正：数量不是「只挂单不成交」的解

同一个 6 agent 的配置，只改 agent 行为，两次实测（都在本项目上真跑）：

| 运行 | agent 数 | 末段表现 |
| --- | --- | --- |
| 修复前 90 秒 | 6 | 50–59s、60–69s、80–89s 成交**均为 0** |
| 修复后 90 秒 | 6 | 成交持续到第 89 秒 |
| 修复后 3 分钟 | 6 | 9 个 20 秒桶**零空桶**，639 笔 / 47,789 股 |

**agent 数一个都没变，僵死没了。** 原因是每个 agent 的冻结资金与冻结持仓是
**各自独立**耗尽的——买方的可用现金被自己挂在盘上的单占住，卖方的可卖持仓同理。
场上 6 个 agent 还是 5 万个 agent，任何一个 agent 走的都是同一条路：

```
每 tick 挂新单 → 冻结一笔额度 → 挂单不撤 → 额度只出不进
→ 若干 tick 后自己的额度见底 → 该 agent 停止下单（continue）
```

**这条路径与「场上有多少个 agent」完全无关。** 5 万个 agent 是 5 万条各自独立的同一条路径，
所以它们会在**同样的轮数**后一起停——把同一个病放大 5 万倍。

更重要的是，5 万个 agent 会在那之前先把别的东西打爆：

| 资源 | 5 万 agent 的后果 |
| --- | --- |
| 平台线程（一 agent 一线程） | 5 万 × 1 MB 栈 ≈ **52 GB** 虚拟内存，直接不可行 |
| 挂单簿 | 不下单撤销则只增不减，无界增长 |
| 撮合吞吐 | 单锁临界区，5 万 agent/tick 排队 |

**你直觉里对的那部分，是我一开始没抓住的重点。**

真实市场确实不会僵死，靠的是海量参与者**不停地撤单、改价、换价**——
挂单在真实市场里是**短命的**。起作用的是「**异质性 + 订单短命**」，不是「数量」本身。
本次修复补的恰恰就是这两样：给 agent 加上了撤单与报价刷新（7.3 会说明，
还有一个更深的频率问题没解决）。

### 7.2 真正的病根在频率：现在一个 agent 相当于 14,400 个真实账户

这是本次查证最有价值的一条。真实市场的标定（来源见第八章）：

| 口径 | 真实市场 | 来源 |
| --- | --- | --- |
| 沪市日均成交笔数 | 81.05 百万笔 | 上交所《上证统计月报》2026-08 |
| 沪市挂牌股票数 | 2,321 只 | 上交所每日概况 |
| **单只股票日均成交** | **34,920 笔/日** | 上两项相除 |
| 平均每笔成交金额 | 10,563 元 | 成交额 ÷ 成交笔数 |
| 沪市投资者数 | 2.64 亿户 | 上交所 2025 年末 |
| 每账户日均成交 | 0.307 笔/日 | 成交笔数 ÷ 投资者数 |
| **每账户日均委托** | **约 3 单/日** | 按 委托:成交 ≈ 10:1 折算 |

而当前系统里一个 `NoiseAgent` 的下单频率是：

```
3 个标的 × 1 单/秒 × 14,400 秒（4 小时连续竞价） = 43,200 单/日
```

**43,200 ÷ 3 ≈ 14,400 倍。**

也就是说，当前每一个 agent 的行为，相当于把 **14,400 个真实投资者的委托
全部压在一个账户上**。这解释了为什么盘口会堆积到需要 `trimQuotes` 去压——
`trimQuotes` 是**止血**，不是治本；真正的治本是：

1. **把下单频率拉回真实量级**（每账户日均个位数）；
2. **让频率本身有分布**（散户慢、游资快、量化极快）。

第 2 条尤其关键：**决策频率的差异本身就是波动率聚集的来源**。
如果 5 万个 agent 全部同频同构，它们产生的只是更平滑的噪声；
大数定律会把厚尾抹平，市场反而**更不像**真实的。

### 7.3 那「5 万个 agent」到底对应多大？

用它自己来算：

| agent 规模 | 单账户日委托 | 日订单总量 | 相当于 |
| --- | --- | --- | --- |
| 5 万 | 3 单（真实频率） | 15.0 万单 | **约 0.43 只真实股票** |
| 5 万 | 43,200 单（现状频率） | 21.6 亿单 | **约 61,855 只股票** |

（单只真实股票日均委托量按 34,920 笔成交 × 10 ≈ 34.9 万单估算。）

**结论很重要：5 万个 agent 配真实频率，正确含义是「把一只股票演真」，不是「演整个市场」。**
这是一个刚好落在射程内的规模——超过它，收益递减而成本陡增。

- 只做一只：5 万 agent 量级；
- 四个档案各一只（A/B/C/D，见 6.1）：合计 20 万 agent 量级；
- 真要做全市场（2,000+ 标的）：那是 10⁷ 量级，**明确不在本项目射程内**。

所以建议的目标是：**四个档案 × 每档案 1–5 万 agent**，而不是「5 万 agent 演全市场」。

### 7.4 要上 5 万，五个东西必须先换掉

1. **线程模型**：一 agent 一平台线程 = 52 GB 虚拟内存，不可行；必须换成下面两条路线之一。
2. **撮合并行**：按 symbol 分片，每分片一把锁，每 tick 批量撮合，而不是每单进一次临界区。
3. **确定性**：撮合用全序 `(价格, 到达时间, 订单ID)`；每个 agent 用独立随机种子（ABIDES 的做法）。
4. **挂单 TTL**：TTL 与每 agent 挂单上限是必需项，不是优化（原因见下面第二张表）。
5. **标定过的频率分布**：见 7.2 与 7.5。

**线程模型的两条路**

| 方案 | 支撑 5 万的成本 | 说明 |
| --- | --- | --- |
| Java 21 虚拟线程 | ≈ 51 MB | `Thread.ofVirtual()`，本项目已是 Java 21 |
| 分片批处理 | 16 线程 × 3,125 agent | **推荐**：时序可控、确定性好 |

推荐分片批处理而不是一 agent 一线程：不是省内存，是为了**确定性**（第 3 点）。

**内存预算（保守估计）**

| 项目 | 5 万 agent |
| --- | --- |
| agent 状态（账户+持仓+参数+历史窗口，2 KB/个） | ≈ 100 MB |
| 真实频率下的在途挂单 | 数百单量级，可忽略 |
| 现状频率下的累计下单量 | 21.6 亿单/日，日志与统计先崩 |

内存不是瓶颈，**订单累计量才是**。

### 7.5 种群设计：让「数量」变成「异质性」

**核心原则：不要写 5 万个策略类。** 5 万个 agent = `策略家族 × 参数分布 × 规模分布 × 频率分布`。

**(1) 规模分布：对数正态，不能等额发钱。**
真实账户规模是严重右偏的。用上交所年鉴的两个实测点反解（持股市值 &lt;10 万占 58.21%、
&lt;50 万占 86.92%），得对数正态参数 `μ = 11.1502, σ = 1.7500`：

| 分位 | 持股市值 |
| --- | --- |
| 50% | 约 7.0 万元 |
| 90% | 约 65.5 万元 |
| 99% | 约 408 万元 |
| 99.9% | 约 1,553 万元 |

给所有 agent 发等额资金，会直接丢掉「少数大账户贡献大部分成交额」这一真实特征。

**(2) 策略家族 × 频率分布。** 频率差异是波动率聚集的来源，必须显式建模：

| 家族 | 账户数占比 | 成交额占比 | 单账户日委托 | 典型行为 |
| --- | --- | --- | --- | --- |
| 散户 | 绝大多数 | 约 82% | 0.5–3 | 追涨杀跌、过度交易、处置效应 |
| 游资 | 极少 | 可观 | 20–200 | 打板、隔日接力、题材驱动 |
| 机构 | 极少 | 约 15% | 拆单 20–100 | 景气轮动、VWAP 分批、长考核 |
| 做市 | 若干 | — | 数千 | 双边报价、持续撤改 |

（散户 82.01% / 机构 14.76% 的交易额占比，来源：上交所统计年鉴 2017。）

**(3) 与第四章的对接。** 第四章的 18 类 agent 是**家族内部的细分**，本章的家族是**配比层**。
两类之间的关系是：先按上表定配比，再在家族内按 4.6 的矩阵分配到四个标的上。

**(4) 行为异质性参数。** 每个 agent 从分布里采样这几个维度，而不是全用默认值：

| 维度 | 含义 |
| --- | --- |
| 风险偏好 | 决定仓位上限与单笔规模 |
| 持仓周期 | 日内 / 数日 / 数月，决定卖出决策的时机 |
| 损失厌恶 | 决定止损行为（真实散户的处置效应） |
| 信息敏感度 | 决定对 `EventFeed` 的响应速度（档案 C/D 的关键） |
| 决策频率 | 由家族决定，见上表 |

### 7.6 顺序不能倒：制度地基必须先于种群规模

有一个证据说明为什么不能先做种群：长测里 `AAPL` 漂移 **−12.36%**、`GOOGL` **+14.85%**。
不是策略不好，是**没有涨跌停，价格就是随机漫游**。

把 5 万个 agent 放进一个没有涨跌停、没有 T+1、没有费用的市场，
得到的不是「更像 A 股」，而是**更多噪声**——因为没有摩擦的市场里，
价格形成的机制本身就是错的，参与者的多样性只会放大这个错误。

所以顺序是：

```
P0 修僵死（已完成）
 → P1 制度地基（涨跌停/T+1/整手/费用/时段）
 → P2 执行架构（分片并行 + 确定性 + TTL）
 → P3 种群设计（本章 7.5）
 → P4 统计指纹验证（7.7）
```

**P2 是「能不能上 5 万」的分水岭；P3 是「上了像不像」的分水岭。**

### 7.7 怎么证明「更像真实市场」：统计指纹

「更加拟合现有市场」不能靠感觉判断，得给出可测的指标。
金融市场的「典型事实」（stylized facts）是现成的验收清单：

| 检验项 | 目标 | 为什么它重要 |
| --- | --- | --- |
| 收益率峰度 | &gt; 3（尖峰厚尾） | 同构 agent 会给出接近正态的分布，这一项直接抓出来 |
| 波动率聚集 | 收益率绝对值的自相关慢衰减 | 需要决策频率异质性，同频 agent 做不出来 |
| 订单流不平衡 | 存在长期记忆 | 需要家族间行为差异 |
| 价格冲击 | 近似 ∝ √成交量 | 需要订单簿有真实深度 |
| 换手率分布 | 右偏，与 6.1 档案对齐 | 与标的档案交叉验证 |

**这张表就是「5 万个 agent 有没有白加」的判据。**
如果加了 5 万个 agent 而这张表没变好，那就说明加的是数量，不是异质性。

### 7.8 路线合并（对 6.2 的增补）

在 6.2 的 P0–P5 中，插入两项：

| 阶段 | 目标 | 关键改动 | 验收方式 |
| --- | --- | --- | --- |
| **P2 执行架构**（新增，插在 P2 之前） | 能支撑 5 万 agent | 分片批处理（而非一 agent 一线程）；按 symbol 并行撮合；订单全序与独立随机种子；挂单 TTL | 5 万 agent 跑满一个交易日不 OOM；同种子两次运行逐笔结果一致 |
| **P3 种群设计**（新增，并入原 P4 之前） | 让数量变成异质性 | 对数正态规模采样；策略家族 × 频率分布；行为异质性参数 | 7.7 的统计指纹表逐项落入容差 |

> 一句话记住这一章：**先把频率拉回真实、把制度补上、把架构换掉，再谈 5 万个 agent。**
> 到那时 5 万是自然的；在那之前 5 万只是把病放大 5 万倍。

## 附：最容易做错的六个地方

1. **以为"没有成交"是市场太简单，其实是订单生命周期缺失。** 这是本次真正踩到的坑：agent 只挂不撤 → 冻结额永不释放 → 全场停止下单 → 盘口只剩陈旧挂单。所有限价单都有生命期，做市商必须能撤单改价；**没有这条，加多少 agent 都是往一个死掉的市场里加。**
2. **让限价单价格等于最新价。** 最新价必然落在买一卖一之间，价格等于最新价的限价单**永远不成交**。想成交就必须主动吃对手价（买用卖一、卖用买一）。这个错误不会报错，只会让某个 agent 静默地"一期都不交易"。
3. **只把时间调长，就以为在做长期交易。** 长期是结算层 + 持仓层 + 考核层三层结构，缺一层就只是"加长版的日内市场"。
4. **口径混用。** 不复权价算长期收益、用初始资金当收益率分母、分红当成额外收益——这类错误不会报错，只会让结论悄悄偏掉。你们已经踩过一次（`seededHoldingsDoNotInflateReturnRate`），要当成一类风险来防。
5. **所有 agent 共用一个决策周期。** 市场上资金的时间尺度不同，是长期市场行为的根源。如果所有 agent 都是"每秒看一次行情然后决策"，加多少个 agent 都不会更像真实市场。
6. **不核对下单频率就扩 agent 数量。** 这是第 2 条的定量版本：真实市场每账户日均委托只有**个位数**，而当前系统一个 agent 是 **43,200 单/日**（3 标的 × 1 单/秒 × 14,400 秒），高了约 **14,400 倍**。在这个频率上扩到 5 万个 agent，等于把数亿个真实投资者的委托量塞进一只股票。**扩规模之前先标定频率**，否则得到的不是"更真实"，而是"更贵"。

> **另一个实测发现（P1 的理由）**：本次修复后连跑 3 分钟，因为没有涨跌幅约束，
> 价格会随机漫游跑飞——实测 AAPL 已到 -12.36%、GOOGL 到 +14.85%，
> 而 A 股主板单个交易日不可能出现这种幅度。**这正好说明涨跌停校验必须在标的换掉的同时就加上**，
> 否则长期跑下去的"价格"没有可比性。相关数据见 `docs/05-运行与验证记录.md`。
