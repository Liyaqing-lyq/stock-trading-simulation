# 治理事实索引只读对照设计

目标：检验同一份角色输入增加有来源、带作用域的机器可读事实索引，能否减少“当前无经理/必须等经理提预算/旧会阻断等于无新会议权限”的误判。用户已要求自主持续推进并明确免再次确认；本设计由执行者选择，不称用户已逐项认可。

依据：Task14原有36次对照已改善部分当前状态识别，仍有等待必要性无据；Task15一次独立抽取能指出主席权和旧会范围，却把开局边界混作当前状态、漏掉普通董事提案权。当前v5实跑也出现经理无预算而主席等经理提案的循环。

方案取舍：直接要求召集/批准会代做策略，排除；立即更换模型同时改变多项因素，暂不选；本轮选择只添加事实索引，原输入、模型、system、工具合同及执行规则不变。它是输入表达的一个打包干预，不能把结果归因于索引内部某一字段。

仅做世界外建议对照，不改生产源文件。固定已封存的call386、426、537、225的contextual输入，原臂逐字不变，新臂仅新增顶层governanceFactIndex；每臂每切点3次，24次HTTP，10分钟，不重试。交错原/新次序。模型路由和2048输出上限取原call，沿用PLANNING_SYSTEM_TEXT。只发送已有虚构角色资料，不发送world cut、文件路径、凭据或全知状态。

索引逐公司包含：当前观察时点、当前席位和召集权、activeManagers及预算期间/授权原样值，并附JSON Pointer；开局资料只给doc/version/readAt/asOf及其原文路径，明确其时点与当前不同；从已有procedure原文抄录预算提案权限句和新会创建句，并保留来源路径；旧会议planningPrerequisites关联meetingId，标明作用于该会议。不得增加候选、预算金额、时点选择、优先级、下一动作或“应该”评价，不生成经理专属限制，不宣称权限可保证执行成功。

验收：预检原臂SHA、新臂删除新增字段后与原输入语义完全相等、所有指针可解析且引用值精确相同，输入长度限制沿旧probe；保存24份原输入/回执/用量/提供方来源。输出先过现有严格角色回复合同，再人工核验当前状态、权限/阻断理由，WAIT本身不是错误；建议数不等于实际动作。若无改善保留失败，不扩大运行掩盖结果；有改善也须另立新版本实现/恢复验证，再做真实经营。
