# M4b.1 资料版本、实际阅读与个人经历纯核

依据基线§7/8/9。接在已验收RoleAccess纯核之后，先验证信息如何进入人物经历；它不等于媒体自主采编、六层认知/遗忘/偏信或真实LLM已经运行。

## 范围

在既有C隔离树仅新增`world/InformationModel.java`与测试，不改RoleAccess/Board/Model/Runtime/旧测试/配置。纯不可变候选，无I/O/时钟/网络/金额。依据同一OpeningRegistry和传入的最新RoleAccess.State判定；后续Runtime必须固定该registry并验证RoleAccess与开局归属一致，不能信任任意JSON授权。

## 信息版本与可见投影

- 资料有公开opaque文档ID、long版本、标题、正文、登记作者/发布者、发布时间、正阅读耗时、受众、公开来源描述，以及只供管理审计的内部源标识。受众仅PUBLIC、ORGANIZATION(一个组织)、DIRECT(一个人物)。无额外角色、群历史或现实文件名映射。
- 文档版本只追加；同一文档的发布者/受众固定、版本连续递增、发布时间单调，标题/正文/公开来源描述按版本冻结。需改变受众时另发新文档，不能让新版覆盖旧文或悄悄扩大旧文受众。内部源标识用于审计，不返回给角色，也不据转载次数自动增加独立证据。
- PUBLIC可由登记人物查询；组织资料须RoleAccess.READ_ORGANIZATION_FILE当前获准；DIRECT只对应人物。查询只返回其可见资料的ID/标题/版本/公开发布者/发布时间，**不返回正文、内部源标识、全局数量/位置、隐藏版本**。未公开资料不显示。不得返回原始State/Document给角色。
- 角色全文只来自本人已完成的ReadObservation投影，包含所读固定版本、当时标题/正文/公开来源描述与实际完成时点；不含内部源ID。取得目录/开始阅读都不构成已知全文或可用引用。

## 耗时、授权与经历

- startRead使用明确版本，在开始时检查已发布与权限、预留人物工时，due=now+版本固定正耗时，溢出提前拒绝。每个人同时最多一个活动阅读；不同人物互不阻塞，ID运行内不复用。
- completeRead到期再用最新完整任职历史，按固定due时刻复核权限；未到期不完成。COMPLETED与DENIED都在due终结，不因迟交延长工时。due之前或恰好due离任则拒绝，due之后才离任不抹去已读，后来重新任职不能倒填due时无权的经历；false候选若改变工作状态必须保留。暂停/世界提交属于未来Runtime，不读墙钟模拟完成。
- cancelRead在开始后可取消未完成阅读，记录取消时点/已花模拟时间，释放工时，无全文经历。首版不模拟半篇阅读；不得把全部正文提前喂给人物。完成/取消/拒绝后重复完成不产生第二份经历。
- 已实际读过的v1在离职后仍属于个人经历；组织新版访问被拒。新入职者仅能查授权目录，个人经历为空，不能复制前任记忆。阅读中发布v2不替换正在读的v1，需要另付工时获取v2。
- canCite(person,docId,version,now)只在本人该版本实际完成后成立；不能引用仅见标题、别人的经历、未来完成或虚构经历。它不判断自然语言是否真实，正文观点/指令不会增加RoleAccess权限或修改权威账。

## 必须先RED的验收

- [ ] 公共/组织/私信受众与未知人物、未发布版本正确；目录投影无全文/内部源ID/隐藏计数。
- [ ] 10:00开始30分钟资料，10:05仍无正文/引用，10:30才得到完整固定版本；due溢出/0耗时拒绝。
- [ ] 阅读中更新v2不换v1；完成v1后引用v2仍拒，另读v2后两份经历按真实时点保留。
- [ ] 同人物工时冲突、不同人物并行、取消与重复完成、开始后离职到期拒绝并释放工时。
- [ ] 离职保留过去已读经历、失去新档案，新人不克隆；注入正文不授予工具权限。
- [ ] 版本/受众/发布者不可覆盖，真实引用与猜测不混同；深不可变/JSON往返，接收顺序与时间确定。
- [ ] 定向/隔离全套/Javadoc；私有错误副本提前给正文、略过到期授权、读最新版替代固定版本，均应被新断言捕获。

只有纯核验收后才接唯一世界日志的持久阅读完成/观察投递；不把此处候选执行说成角色已经在真实世界里阅读。
