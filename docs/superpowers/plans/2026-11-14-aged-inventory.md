# 陈酿库存与有限渠道实施 Plan

依据总体基线的十类公司机制与公司池研究。参数均为 EXP 模拟假设；先接受纯 Java 核心，再接唯一世界的任职、预算、调度、恢复、报告及 Web，不另建运行器。纯核修2已独立接受并接入主树，尚未正式组合验收；世界与 Web 尚未启用。

## 冻结的经营口径

- 原料到货、转产、成熟、寄售发出、终端售出、回款各有真实状态。发货不确认收入，回款不再次确认收入；成熟和货架期按冻结时点判断。
- 公司、供应商、加工方、费用收款方、渠道和终端消费者均使用有限的真实现金账户；终端付款给渠道，渠道再按应收付款给公司。缺钱不得凭空补足。
- 数量使用 long；各 lot 的总成本和总预收以分为权威，部分消耗按累计比例减已分配额计算，最后一笔结清尾差。展示单位成本不能反算替代总成本。
- 寄售价格在发货时冻结，调价只影响新发货；底价是开局 EXP 授权参数，不冒充尚未发生的董事决议。终端需求来自冻结、有界序列，请求不足条件时整笔拒绝且不占用配额。
- 应收、合同负债分渠道保留总额，不用净额掩盖。货物报损或过期后尚未抵扣的预收转为退款应付；未退款仍是债务，不能变成利润。
- 固定费到期计提，现金不足保留应付。每个候选先核不变量，再交给世界持久确认；后来的关期失败不回滚已经完成的过去动作。
- 产能按整期累计使用，拒绝请求不占配额；下期才重置。过期批次即使尚未关期也不能出售。
- 成本分配同时扣除累计出库与报损成本；已退款加退款应付必须等于预收减销售抵扣减合同负债。允许真实亏损导致负权益，仍须账平。公司不得与实际付款对手是同一账户，外部角色可以合法共享账户。

## 实施与验收

1. 纯核：FIFO 多批次、产能/需求/现金不足、分币尾差、成熟/过期、退款和固定费应付；独立 Python 数例与 Java 对照，逐主体账平和跨主体现金守恒。报告允许亏损，不为凑原设计数字改规则。
2. 世界：经理观察任职与开始/完成权限交集；共享真实采购/人工预算、唯一账户、时间与期次；原命令完整派生、写入故障恢复和旧档兼容。
3. 公司：库存与在途寄售只计一次，费用/应收/合同负债/退款应付进入同一公司报表；实际披露与董事考核分别执行。初始权益不重置。
4. Web：批次成熟和货架时间线、发货/售出/回款分列、缺钱与退款义务可见；God 与经理/投资者采用各自真实权限。组合正式验收、评分映射、运行证据及 PR review 齐备后才称交付。

原设计中的通用 Gate/StageRecognition 抽象、无终端付款的销售以及先提交再检查账平方案未接受。保持现有工程、制造、董事会模型的既有行为，新增代码仅服务上述陈酿机制。
