# M4j.2 一对一消息运行与 Web 合同

本合同优先于social-runtime-preparation/contract-proposal-v2.md。依赖M4j.1纯核独审接受；schema17固定用于本模块，工具合同新增v5，旧v1–v4文本及输入保持原样。目标是普通人物真实异步交流和审计，群组/转发/平台后继完成。

## 接入结构

- 整个世界一个SocialRun，冻结纯核Config、blockMillis正工时、受信ContactEntry列表；不建立第二份正文、阅读账、联系人权限或现金。WorldState新增可空social，仅新schema17写出；旧schema和开局内容摘要不变。v5保留v4采访/私证/媒体输入与能力，再追加social。
- `social.send(toPartyId, channel, title, body)`、`social.block(targetPartyId)`、`social.unblock(targetPartyId)`。不让模型自填caller、命令ID、消息ID、文档ID、事件序号或可信来源。可达从实际读取且可回忆的可信入口/实际Social来信派生，不需要模型重复提交entryDocId。messageId按已冻结纯核caller+commandId生成。
- 所有普通登记PERSON可使用，不依赖基金或记者岗。决定轮仍受人物预算、场景route和单焦点约束；社交采用既有media场景路由/key槽位，不增加第六场景。场景开启不代替权限，角色离职不丧失本人普通通信权。
- 人物工具不能暴露所有世界人员名单。联系人只来自实际读且可回忆的入口或来信；同一份文档提及人名不自动授权联系。自由文本是未经核实陈述，不可成为结构化引用证明。

## 时序与原子性

1. send的真实动作开始批次调用beginSend，写Draft、唯一正文payload、占用本人正工时、排SOCIAL_FINISH_V1并落命令和事件。提供方回执到达、意图持久化与模拟动作开始分开：回执早于决定barrier时，只保存意图及开始排程；世界到barrier才按当时权限/可达/回忆/单焦点开始。不得提前修改实际社交clock，不得等完成帧再把过去startedAt传给当前纯核补begin。开始后仍在完成时复核。
2. 业务失败（忙碌、不可达等）同批记录首次裁决，不建Draft/工时/完成任务，不混成TECH_FAIL。重复同内容使用已有命令结果，不回滚新state；异内容冲突。
   模型选择与业务执行分开：模型已返回send意图时，不得改写成role.wait或伪造一份观望回执来结算。优先保留INTENT和原回执，另记录明确的派发拒绝及原因；必要增加新schema专用拒绝状态，旧v1–v4验证口径不变。拒绝必须有真实结果记录而非虚构完成任务。
3. 到期finish只处理真实Draft；成功排最早completion+deliveryMillis的SOCIAL_DELIVER_V1，deliveryMillis>=1。未到期不补事件，终止不发文档。全局单调时间，阶段不得回跳。
4. 送达时Information DIRECT文档、DELIVERED元数据、报告/事件/快照同批提交；收件人忙碌照常投递，阅读另占工时。投递前人物目录和猜文档ID均不能见信；投递不是已读、相信或回复。
5. block/unblock是正工时动作（Config.blockMillis，实验默认250毫秒），走相同单焦点和结果记录；屏蔽与投递同刻按已固定世界phase顺序执行，不偷偷优先。解除屏蔽不复活已经BLOCKED终态的旧消息。
6. 将社交占时接入全部既有注意力动作：阅读、采编、采访和决定；反向也拒。不同人同刻独立；同轮其他人成功不受一个人的技术失败或业务拒绝污染。

早回执不能把其他人物更早到期的动作推迟到自己的barrier，也不能令当前合法通信被未来clock拒绝。已发生的社交报告时点不超过所在世界帧；未来开始只属于pending。早回执与barrier回执对无关人物的同一既定完成时点应一致；逆序回执、开始前屏蔽/遗忘、开始排程恢复与重放均须验证。若到实际开始才业务拒绝，保留原意图和真实拒绝报告，不制造完成任务。该修订只适用于新schema17，旧回执协议保持。

## 信息投影

- input.social /人物页仅本人inbox、outbox和合法联系人。inbox只含实际送达信封标识、真实发件人、文档版本/标题/时点、本人是否读过；全文沿已有实际阅读/回忆通道。outbox可见本人发送结果，未送达统一UNREACHABLE，不泄漏被屏蔽/目标是否存在，不提供对方已读回执。
- 管理员可看真实送达/拒绝/屏蔽原因和来源审计，但管理查询不形成角色经历。人物端不包含全局序号、他人消息/数量、私密root、未读正文、完整key。
- 保存决定输入后只按其历史快照重建验证，不用当前联系人、未来阅读或之后的屏蔽状态反填。所有场景参数标实验未校准。

## 阅读历史、回忆资格与输入窗口的区别（联调澄清）

一次决定的回忆条数/正文长度上限只是输入窗口，不得作为“没有读过”或“已经遗忘”的证据。消息已读标记及管理员已读审计按截至时点真实完成阅读历史计算；是否仍能回忆正文/地址按最近完成阅读的衰减阈值计算，与既有社交纯核一致。真正遗忘可隐藏正文和地址，但不能抹去已经发生的阅读事实。

人物合法联系地址包括仍可回忆的可信入口及实际读过来信的真实发件地址；二者均不按本轮selected条数截断，也不根据对方是否屏蔽自己隐藏地址（避免泄露对方偏好）。输入的正文仍沿既有有界回忆窗口，不自动塞入全部历史。

Web与模型输入复用同一联系人/已读投影。Web展示某封已读信正文时，可走一个仅限本人实际收信、真实完成阅读且仍通过回忆阈值的只读查询；不得从管理员全文表无条件取正文。该查询不产生阅读、不推进世界、不改变模型输入窗口。9封逐封真实送达与阅读后，早先信件不因maxItems=8重新变成未读；真正衰减后已读事实保留、正文不再返回。旧v1–v4语义不变。

## 恢复与旧档

- 冻结开局Config并逐字段核；从前帧重演begin/finish/deliver/block，比较实际状态、pending、原命令和结果、调度事件、文档，而非仅核digest。覆盖原文+摘要+pending+commands+outcomes+TASK_SCHEDULED一起自洽伪造的拒绝。
- partial-write及force失败只留旧或完整新批次；重开/重试单一效果。独立进程在写信中/排队中/送达后恢复。
- 真实冻结旧16客户端和旧runtime读取新实现续写的旧16副本；原件不改、旧class不重编。旧≤16拒新工具/任务/角色，续写仍旧schema，JSON不增加social空键。schema17不要求旧程序可读。

## 最小交付与实测

后端、WorldWebScenario社会实验档、Web管理员消息审计/人物信封与实际阅读展示分开单写者实施，最后合并验收。独立社交档必须继承已启用的采访/证据能力及联系人入口，禁止凭新增模式悄悄移除既有能力。最终统一运行选择与多公司工作台仍按M6完成，不称实验档就是总体初版。

真实HTTP输入驱动至少两个普通非媒体人物：未读不能发→读入口→写信/完成/延迟投递→收件人只见信封→真实读→回复；读前回复拒绝、第三人不可见、忙时异步投递。再验写信中屏蔽/遗忘、排队屏蔽、投递后屏蔽历史保留、无回执泄露、同人冲突与不同人并行、命令重放不回滚、0TECH_FAIL掩盖、v1–v4输入不变、v5既有能力齐全。浏览器检查新页面/角色切换/五Key遮罩/错误空日志；真实provider调用可先0，脚本结果不得伪称真实自主行为。
