# 银行 Java 实施与验收合同

依据总体基线及已独审接受的v8参考核算。先接纯核，后以schema19接唯一世界运行；不因纯核通过宣称银行全部完成。金额BigDecimal scale2、数量long，公共API中文Javadoc。

## 权威账与边界

- 全部现金与银行准备金只存CashLedger；银行存款是银行负债和客户债权，不能再算成现金。SETTLE各持有者DUE由全部现金派生，不能另存可修改的准备金或DUE。
- 银行账簿、贷款、备查、准备、有限救助、命令/来源与现金变化形成一个候选，由唯一WorldCommit持久化。不建第二Runtime/journal/scheduler。跨行一次现金转移同时更新两行存款负债；客户正余额和贷方总账负号明确区分。
- 开局绑定OpeningRegistry的组织/账户；迁移必须实际转走原现金且origin唯一，不给银行复制资本或重复发行货币。规则档案深拷贝并冻结指纹，新激活需完整校验，新运行显式迁移；旧档不升级。
- 合法业务拒绝绑定commandId、规范请求和原回执；重放返回原结果且不回滚当前状态，补资后重试需新ID。同ID异请求冲突。不可解析协议错误可不消费ID；持久化故障整个候选不应用。此规则明确强化v8“业务拒绝不记ID”的语义。

## 实施顺序

1. Java纯核：规则声明宇宙与目录校验、完整已启用账簿、存取/跨行、贷款/还本/第三支付、减值/核销/回收/豁免、有限救助及提供者账。现于隔离目录实施，尚未接主树。
2. 完整金融条款：利息计提与支付、到期、承诺动用、救助设施期限和价格、押品实际留置、处置优先级与损失分担。先冻结具体条款再实现，不能将参考未做事项算作已完成。
3. schema19世界桥：同一账户/任职/时间/输入工具/恢复，与schema18经营/治理闭合；托管、跨行支付与实际证券结算联合接入。
4. Web与实验：God全账审计和本人权限投影；来源/实验假设/未实现项可见，正常、违约、流动性不足与处置结果可复算。完成独审、正式验证、PR及人工review要求。

## 托管另立接缝

证券lots表示股数，不等于客户现金受益权。托管受益权须与真实专户资产和对客户负债对应，机构净资产抵销，客户只计一次；不把WorldExchange订单冻结当托管账户。不得先生成独立股数影子账再称接入撮合。

v2草稿“先收现金后存银行”的中间态不能仍要求存款专户余额等于全部受益权：后继应选择同一原子批，或明确托管现金加存款的覆盖口径。纯核第一步暂不实现CUSTODY_TRADE；该范围保留在步骤3，不删除需求。

## 必须保留的反例

- v8 R1原顺序：放贷1000、还本200→合同/表内800；计提并核销400→表内400/备查400；此后第三支付150→合同650/备查250；豁免400拒绝，豁免250后合同400/表内400/备查0。第三支付不自动代位。
- Java扩展另测核销前第三支付：1000−200−150→合同/表内650、备查0，不能确认回收收入；之后计提核销400→表内250/备查400。此时豁免400在备查上限内可接受；若只豁免250则合同400/表内250/备查150。不能把两个不同顺序的末态拼接。v8第三支付原函数只处理核销后追索，核销前扩展不是v8已经证明的事实。
- 候选后准入：1180允许/1181拒绝；资本不足不应阻止合法还本。金额非正、超精度及溢出、原子回滚、完整参与者和origin绑定均须拒绝或保持原状态。
- R5：提供者减值不抹银行名义债；还250并豁免250使银行权益增250/提供者减250。挤提后准备金250，另三笔10元业务后240，两个时点分列。
