# M5a 工程回款纯核实施合同

## 0 冻结与范围

本稿把 v3/v4/v5 中已接受的规则合并为**单一可读基线**，后续纯核实现只读这一份，不再拼接旧版。
Root授权按本合同在独立目录实现纯核；尚未授权世界运行桥或Web。准备数例保留为独立复算参照。

## 1 冻结的最小合同条款（实验假设）

- 数量单位为“标准工日”，金额 `BigDecimal`（2 位），单价成本 4 位；合同价 `V=单价×数量`。
- 阶段：若干个**单位数**阶段（求和=总量），每阶段完工后可验收并开票。
- 预收 `A = round2(V×advanceBp/10000)`；质保 `R = round2(V×retentionBp/10000)`；
  约束 `advanceBp+retentionBp ≤ 10000`，余款由阶段开票覆盖（不设 progressBp）。
- **质保只采用 `TIME_ONLY`**：阶段金额一旦验收并开票，即取得无条件付款权；质保部分是
  **未到期应收**（有固定到期日），到期前不得强收，但可因真实违约评估计提减值。
- 未验收、或尚未取得无条件付款权的金额仍是**合同资产**，单列，不搬入应收、也不搬入备查。
- **不支持**“最终验收/质量合格后才付质保”等附加条件模式；配置出现该模式必须显式拒绝
  （`RETENTION_CONDITION_UNSUPPORTED`），不得静默按 TIME_ONLY 解释。
- 这是为可核对性冻结的实验条款，不概括所有工程合同，不声称行业惯例或会计准则。

## 2 科目分层与恒等式（修正 v5 正文的口径错误）

科目：现金（唯一 `CashLedger.CashAccount` 表）、到期应收、未到期质保应收、合同资产、
减值准备（contra-asset）、履约成本、合同负债、应付、备查权利（账面 0）、累计损益。

- `应收毛额 = 到期应收 + 未到期质保应收`；`净应收 = 毛额 − 减值准备`。
- `客户合同义务 = 应收毛额 + 合同资产 + 备查权利`（毛额口径）。
- `客户合同义务 = 净债权 + 减值准备 + 备查权利`（净额口径）。
- 当且仅当 `减值准备 = 0` 时，`净债权 + 备查` 才恰好等于客户义务；一般情况下
  **必须保留 allowance 项**。减值造成的双方账面差异是估值差异，不是守恒失败，不强行配平。

## 3 记账规则（合并已接受口径）

| 动作 | 分录 | 禁止 |
| --- | --- | --- |
| 签约 | 只登记合同与实验容量 | 不动任何金额科目 |
| 预收 | 公司现金+；合同负债+；客户现金−、客户预付+ | 不确认收入、不生应收 |
| 履约投入 | 履约成本+；人工付现（公司现金→作业方）；分包计应付/供应商应收 | 不确认收入 |
| 验收 | 收入+毛额；合同负债−`min(余额,毛额)`；合同资产+余额；客户工程资产+毛额、客户应付+（毛额−预付消耗） | 不按比例自报进度 |
| 开票 | 合同资产−无条件额；到期应收+（无条件−质保扣留）；未到期质保应收+扣留 | 不再冲预收、不再确认收入 |
| 到期回款 | 现金双边±；到期应收−；客户应付− | 不动未到期质保 |
| 质保到期回款 | 现金双边±；未到期质保应收−；客户应付− | 未到期不得强收 |
| 计提减值 | 减值准备+；减值损失+ | 不改客户义务 |
| 核销 | 毛额−；减值准备−；备查+；金额不得超过已计提减值 | 不确认新损失、不核销未减值金额 |
| 真实回收 | 现金双边±；备查−；客户应付−；收回收益+ | 不再确认原收入 |
| 终止剩余履约 | 履约成本→损失；已验收阶段应收保留（不搬备查） | 不把未满足条件变成永久备查 |
| 显式豁免 | 备查−（无损益）；应收毛额−（按账面净值计损失）；客户应付−；客户权益+ | 不能由核销自动触发 |
| 支付供应商 | 现金双边±；应付−；供应商应收− | 不再计费用 |

## 4 债权状态机

`合同资产`（有条件/未开票）→ 开票 → `到期应收` 与 `未到期质保应收`（均为毛额、无条件）→
到期回款 / 计提减值 → `核销`（仅限已减值金额）→ `备查`（账面 0）→ 真实回收（备查与义务同减，
确认收回收益）→ 剩余部分可经**独立豁免**解除义务（按账面净值计损失）。
每一转移都保留 `gross / allowance / memo / obligation` 四层，不合并、不互相替代。

## 6 失败边界（实现必须真跑到）

条款不闭合、费率越界、阶段单位和不等于总量、金额非 2 位；重复标识/命令内容冲突；
预收超 `A`、未签约预收；投入超剩余总量、人工现金不足（整笔拒绝）；验收早于完工或超完工量
（完工来自正耗时任务，验收来自外部规则，LLM 不能自报）；开票跳期/重复/未验收；
未到期质保强收、超应收回款、付款方现金不足（只标逾期，不部分入账）；核销超已计提减值；
非 `TIME_ONLY` 模式；终止时试图把未满足条件搬入备查；`validate` 不平衡时抛 `IOException`，
由 `commitAndApply` 置 `paused` 并保留旧快照。

## 7 最小接口（纯核，无 IO/时钟/随机）

```java
record Terms(int advanceBp, int retentionBp, int netDays, int retentionNetDays,
             RetentionMode mode, long[] trancheUnits)   // mode 只接受 TIME_ONLY
record Claim(BigDecimal gross, BigDecimal allowance, BigDecimal memo)  // 只读投影，不新建现金账
static Outcome investWork(...); static Outcome accept(...); static Outcome invoice(...);
static Outcome collectDue(...); static Outcome collectRetention(..., long now);
static Outcome impair(...); static Outcome writeOff(..., BigDecimal amount);
static Outcome recover(...); static Outcome waive(..., String reason);
static Report validate(State, Map<String,CashAccount>);
```
金额一律 `BigDecimal`，数量与时间 `long`；不引入 Money/Quantity 包装；报告字段与 v4 相同并增加
`arCurrent / arRetention / allowance / memo / obligation`。

## Root实施边界

只新增EngineeringModel与有意义测试，不改既有世界/银行/制造/董事会/现金类。金额BigDecimal，数量long；Terms阶段集合不可变防外部修改；纯核失败用结果/合法参数异常，不引入IO异常/暂停世界职责。现金变更计划调用现有CashLedger并返回同一权威映射的候选，不在本模块另存余额。投入完成须核正耗时和资源；验收来自可信外部结果，不能由经理文本自报。动作commandId/业务ID的幂等、同ID异内容、越权者探测等按既有模式明确。

拒绝不支持的条件留款模式；TIME_ONLY是实验合同假设，不可称行业标准。财务估值与合同义务区分，部分减值/部分核销/核销后回收/仍在账债权豁免必须有测试；豁免不得重复损失或抹掉未处理准备。单次付款失败双方均不变。两种完整合同路径及小额尾差用独立Decimal结果复算。v6正文关于net+memo相等的条件已由Root纠正：只需allowance=0，memo无需为0。

主树接入前由另一Hermes独审，最终正式门槛复用项目规则；此阶段不宣称银行、工程运行桥、多公司或总体初版完成。

## 首轮反例后的规则澄清

- 验收与开票分别推进。下一验收阶段从已验收单位及既有阶段记录派生，不能用开票游标代替；允许先验收多个真实完工阶段再按顺序开票。
- 工单成本按合同累计投入量的目标成本差额分配；人工按累计已分配成本的目标人工差额分配，分包为本单成本减人工。不得每单独立四舍五入后把负尾差留给最后一单。各累计前缀应与独立 Decimal 复算一致；重新划分工单可改变单笔分配，不改变同一累计量与完整合同总额。
- 终止关闭未完工工单，之后不能继续增加完工量；已投入成本只转损失一次。
- `acceptanceRef` 在纯核内只是受信调用者提供的引用，不是已验证的外部证据。世界桥必须先以客户或可信规则事件核对合同、阶段、数量、时点并去重，再调用纯核；不得把此接口直接提供给经理或模型。增加字段或非空字符串检查本身不能建立信任。
- 外部资本流与合同外付款须在后续桥合同中显式核对权益和会计归属，禁止自动重设初始权益以掩盖不平衡；当前纯核不声称兼容任意外部现金改动。
