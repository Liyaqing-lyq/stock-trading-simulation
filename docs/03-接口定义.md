# 03 接口定义

> 本文记录现有 Java 接口，不是扩展世界的完整目标契约。身份与账户分离、完整组合估值、权限、持久提交、恢复等新语义以[总体设计基线](design/总体设计基线.md)为准；实施时逐项迁移与回归，不能静默改变现有字段含义。这里描述的 API 并不表明扩展能力已完成。

本文档给出对外/跨模块接口的契约：职责、方法语义、前置/后置条件、线程安全与异常行为。
实现细节见 `docs/02-系统架构设计.md`。

## 1. 领域模型（`edu.cufe.auction.model`，全部不可变或受控可变）

### 1.1 `OrderRequest`（不可变）
- 工厂方法：`limit(agentId, symbol, side, price, quantity)`、`market(agentId, symbol, side, quantity)`。
- 构造即校验：`agentId/symbol` 非空、`quantity > 0`、限价单必须给出正 `price`、
  市价单不得携带 `price`；违规抛 `IllegalArgumentException`。
- 线程安全：不可变，可跨线程自由传递。

### 1.2 `Order`
- 由引擎创建，携带引擎分配的 `orderId` 与时间优先序号 `sequence`。
- 只读字段：`agentId/symbol/side/type/limitPrice/quantity/sequence`。
- 可变字段：`filledQuantity`、`status` —— **只允许 `MatchingEngine` 在锁内修改**
  （`addFill`/`markCancelled` 已公开但标注为引擎专用）。
- `canMatchAt(price)`：市价单恒为 true；限价买单要求 `price <= limitPrice`，限价卖单要求 `price >= limitPrice`。

### 1.3 `OrderResult`
- `isAccepted()`：受理与否；被拒时 `getReason()` 给出可读原因，`getOrder()` 为 null，`getStatus()` 为 `REJECTED`。
- 被受理时：`getOrder()` 为终态订单，`getTrades()` 为不可变的本次成交列表。
- 线程安全：只读快照。

### 1.4 `Trade` / `PriceLevel` / `OrderBookSnapshot` / `MarketSnapshot`
- 全部为不可变只读快照；`MarketSnapshot#getChangePercent()` 相对配置参考价计算涨跌幅。
- `OrderBookSnapshot#getBestBid/getBestAsk/getSpread` 空侧返回 null（调用方必须判空）。

## 2. 引擎接口

### 2.1 `OrderGateway`（agent/GUI 的唯一下单入口）
| 方法 | 契约 |
| --- | --- |
| `OrderResult submit(OrderRequest)` | 线程安全，可并发调用；**不抛业务异常**（校验失败通过 `OrderResult#isAccepted=false` 表达）；参数为 null 抛 `NullPointerException` |
| `boolean cancel(long orderId)` | 撤单成功返回 true；订单不存在或已终结返回 false（幂等，不抛异常） |

### 2.2 `MatchingEngine`（`implements OrderGateway`）
- 构造参数：`AccountManager`、`MarketDataPublisher`、`Map<symbol, 参考价>`；标的空间固定，构造后不可增删。
- `submit` 语义（全程持锁）：
  1. 市场已收盘 → 拒绝；
  2. 未知标的 / 未知账户 → 拒绝；
  3. 买单计算每股冻结额：限价单取限价，市价单取当时卖一价（无卖盘 → 拒绝）；
  4. `Account#reserve` 失败 → 拒绝（资金不足 / 可卖持仓不足）；
  5. 撮合循环：始终取对手方最优挂单，**价格不交叉即停**，成交价取被动方价格；
     买方可用额度 = 该单剩余冻结 + 账户可用现金，触顶即停止吃单（账户不会被打成负现金）；
  6. 限价单剩余挂入订单簿；市价单剩余撤销并释放冻结；
  7. 锁外：逐笔广播成交 + 广播行情快照 + 通知 `EngineListener`。
- `closeMarket()`：置收盘标志、撤销全部挂单并释放冻结，返回撤单笔数；此后 `submit` 一律拒绝。
- `snapshot(symbol, depth)` / `marketSnapshot(symbol, depth)`：线程安全只读；标的不存在返回 null。
- `lastPrices()`：各标的最新价，无成交时用配置参考价兜底（供估值使用）。
- 异常策略：`EngineListener` 抛出的 `RuntimeException` 被捕获并打印，不影响撮合结果。

### 2.3 `OrderBook`（包内可见的可变结构）
- **不是线程安全的**，所有方法要求调用方持有引擎锁。
- `post(Order)`：仅接受限价单；同价按 FIFO 追加。
- `bestOpposite(Side)`：返回对手方最优挂单；空侧返回 null。
- `remove(Order)`：从价位队列与 id 索引中删除，价位空则移除该档。
- `snapshot(depth)`：聚合同价剩余量，买盘价格降序、卖盘价格升序。

### 2.4 `EngineListener`
- `onOrderAccepted(Order, List<Trade>)`、`onOrderRejected(OrderRequest, String)`、`onOrderCancelled(Order)`。
- 回调在**引擎锁外**触发，允许做 I/O；实现不得重入引擎的变更方法。

## 3. 账户接口（`account` 包）

| 方法 | 契约 |
| --- | --- |
| `boolean reserve(orderId, symbol, side, perShare, quantity)` | 买入：按 `perShare × quantity` 冻结现金；卖出：冻结持仓。额度不足返回 false 且**不改变任何状态**；同一 orderId 重复冻结抛 `IllegalStateException` |
| `void release(orderId)` | 释放该单剩余冻结，幂等（无记录时静默返回） |
| `void settleBuy(orderId, symbol, price, quantity)` | 释放对应冻结、按实际成本扣现金、增加持仓并更新摊薄成本；价格改善的差额退回可用现金 |
| `BigDecimal settleSell(orderId, symbol, price, quantity)` | 释放冻结持仓、增加现金、累计已实现盈亏，返回本笔盈亏 |
| `BigDecimal equity(lastPrices)` | 现金（含冻结）+ Σ(持仓 × 最新价)；缺价时用成本价兜底 |
| `BigDecimal getInitialEquity()` | 初始资金 + 初始持仓成本（**收益率基准**） |
| `BigDecimal returnRate(lastPrices)` | `(equity − getInitialEquity()) / getInitialEquity()` |
| `void seedPosition(symbol, quantity, costPrice)` | 仅初始化阶段调用；重复注入同一标的抛 `IllegalStateException` |
| `boolean canAfford(price, quantity)` | 可用现金是否足够 |

线程安全：所有状态访问在账户内部锁上同步；账户层不回调引擎（锁顺序见 `docs/02` 第 4 节）。

`AccountManager`：`createAccount`（重复 id 抛异常）、`getAccount`（不存在抛 `IllegalArgumentException`）、
`ranking(lastPrices)`（按收益率降序，返回 `PerformanceRank` 列表，名次从 1 开始）、`markAllEquity(lastPrices)`。

## 4. 行情接口（`market` 包）

- `MarketDataListener`：`onTrade(Trade)`、`onMarketSnapshot(MarketSnapshot)`，均有空实现；
  **回调在调用线程（业务线程）中执行**，要求快速返回，UI 更新必须 `Platform.runLater`。
- `MarketDataPublisher`：`subscribe/unsubscribe`（`CopyOnWriteArrayList`）、`publishTrade`、`publishSnapshot`；
  监听者异常被捕获并计入 `getListenerErrorCount()`。

## 5. Agent 接口（`agent` 包）

- `TradingAgent`：`getAgentId/getDisplayName/getType`、`onMarketSnapshot(MarketSnapshot)`（广播线程，必须快速返回）、
  `onTick()`（调度线程，做决策与下单）。
- `AbstractTradingAgent`：缓存最新行情（`ConcurrentHashMap`）、统一异常隔离与统计
  （`getSubmittedCount/getRejectedCount/getFilledQuantity`）、`protected submit/cancel`。
- `HumanBrokerAgent`：`placeLimitOrder/placeMarketOrder/requestCancel` 线程安全入队，`onTick()` 出队提交
  （GUI 线程不直接撮合）。
- `NoiseAgent`：在最新价 ±配置比例内随机报价，为市场提供基础流动性；随机种子固定以便复现。
- `MomentumAgent`：短均线 vs 长均线的规则型对照策略（不依赖 API）。
- `LlmTradingAgent`：`getLlmCalls/getLlmFailures/getLlmHolds/getLlmOrdersPlaced` 统计；
  失败回退＝本 tick 观望。

## 6. LLM 接口（`agent.ai` 包）

- `LlmClient#complete(systemPrompt, userPrompt)`：返回模型文本；网络错误/超时/非 200 抛 `IOException`。
- `DeepSeekClient`：OpenAI 兼容 Chat Completions；限流 `llm.rate.limit.ms`、超时 `llm.timeout.ms`、
  `response_format=json_object`；API Key 从环境变量注入（`llm.api.key=${LLM_API_KEY}`），不落仓库。
- `DecisionParser#parse(raw)`：剥离 Markdown 代码块与多余文字，校验 `action/price/quantity`；
  任何非法输入（非法 action、数量 ≤ 0、价格 ≤ 0、非 JSON、空串）一律返回 HOLD，绝不把脏数据交给引擎。
- `PromptBuilder`：行情 + 账户 + 持仓 + JSON 约束的提示词构造。

## 7. 数据与装配接口

- `SimulationConfig`：读取 `config.properties`，支持 `${ENV}` 占位；提供标的、各类 agent 数量/初始资金/
  初始持仓、AI 决策间隔、LLM 参数、输出目录等访问器；`getStocks()` 保持配置顺序。
- `CsvHistoryRecorder`：实现 `EngineListener` + `MarketDataListener`，输出 `orders.csv`/`trades.csv`/`ranking.csv`；
  写入在内部锁上串行化，写失败抛 `UncheckedIOException`。
- `SimulationRunner`：装配全部组件；`start()`（推开盘行情 + 启动调度）、`closeAndRank()`（停调度 → 收盘 → 写排行榜）、
  `firstHumanBroker()`（GUI 下单入口）、`close()`。

这里只描述Java管理夹具，不是角色工具或HTTP服务；制造接口见第9节，治理接口见第10节。完整目标仍以基线与总Plan为准。

| 档案 | 状态schema | 已启用能力 |
| --- | --- | --- |
| cash-world-v1 | 1 | 现金、持久待办、回报 |
| cash-registry-world-v1 | 1 | 上项及开局身份/股份登记 |
| securities-clearing-experiment-v1 | 2 | 上项及T+1批次/卖预留/系统清算夹具 |
| securities-matching-experiment-v1 | 3 | 上项交易原语与持久订单、撮合、买冻结；禁用绕过订单的清算夹具接口 |
| stock-company-experiment-v1 | 4 | 上项及单制造公司经营、有限客户/供应商、自动到货/完工/应收与强制期末；仍为无董事会管理实验 |
| governed-stock-company-experiment-v1 | 5 | 上项及五席预算表决、占用/已花/释放、固定期间证据和强制经营复盘；无角色工具 |
| informed-stock-company-experiment-v1 | 6 | 上项及固定任职授权、资料/阅读活动、自动完成与人物RoleView；仍由可信管理者排程 |

模块表必须与档案精确匹配，模型配置当前为none；旧档案不会静默获得新字段/能力。旧schema续写仍保持原JSON形状。RunManifest与开局参数在首批固定，恢复不重新发钱发股。

`WorldRuntime`排程和推进绑定创建线程，暂停拒绝新排程；读取Snapshot获得同一截止位置的不可变视图。调用方不能把多个时点的账户、订单、批次拼成一份报表。Snapshot公开record增加组件会影响外部按位置构造者；通过runtime.snapshot()读取的既有访问器仍保留。

| 方法组 | 语义 |
| --- | --- |
| scheduleTransfer | 排程现金转移；到期复核owner与余额，matching档案还须扣除活动买冻结 |
| scheduleReserveSell / scheduleCancelSell / scheduleFixtureFill | 仅清算夹具档案；卖批次预留/释放及同批现金股份交割，不是买方下单入口 |
| scheduleOrder | 到期按最新簿/可用资金/合格库存受理，才分配订单号与sequence；排程时不预支未来资金 |
| scheduleCancelOrder | 到期复核目标与属主；只释放未成交量，已成交保留 |
| scheduleCloseMarket | 受信系统动作，撤全簿/释放冻结，保留历史成交并拒后续申报 |
| advanceTo / snapshot | 推进持久待办至给定模拟毫秒；只读取已确认完整状态 |

各schedule方法的commandId/taskId与原参数形成规范化请求：同commandId同内容返回原SCHEDULED，不重新排程；异内容明确拒绝。SCHEDULED只表示待办已可靠受理，不能对外宣称已成交。执行期业务结果在SecuritiesLedger.ActionReport或WorldExchange.OrderReport按taskId读取；后者orderId是新单号或撤单目标，收盘/业务拒绝时为空。

参数/能力/静态权属错误在提交前抛出明确异常；动态钱股不足等到期业务拒绝仍持久保存结果而不改变资产。I/O失败暂停并保留旧钱股/簿/待办，关闭后恢复读取已确认批次，不重跑已确认成交。

世界限价须正且精确到分，数量long，买限先按限价×全量检查冻结资格；市价买按当时卖一×全量检查，后续扫档可按预算截断，余量取消。被动价、同主体防自成交、实验T+1与FIFO由Java裁决。旧课程无价格档案入口的非整分兼容不代表世界档案支持非整分。

`MatchPlanner.plan`输入为已按价格/FIFO排序的报价值副本与解析后的受益主体/预算，输出不可变成交计划；它不读取或修改Order/Account，不读时钟、无I/O。WorldExchange是领域纯候选，证券是否登记由持有OpeningRegistry的Runtime核验。普通角色不得直接获得原始管理Snapshot或自行伪造actorOwnerId调用这些夹具。

## 9. 制造经营管理契约

五参`WorldRuntime(file, manifest, openings, registry, ManufacturingRun.Config)`显式绑定公司财产owner、经营/供应商/客户/人力场地账户及证券。模块和配置必须成对；公司组织与发行人须一致，所有开局错误在创建日志前拒绝。旧构造器仍保留，旧档案序列化省略manufacturing键。

| 排程方法 | 到期语义 |
| --- | --- |
| schedulePurchaseOrder | 有限供应商容量内形成采购单；成功同批排1日后现金交货 |
| scheduleProduction | 10件倍数/不超20/单在制批；耗料、实际人工付款、形成WIP，同批排完工 |
| scheduleSalesContract | 占用当期间客户预算和需求；未来同期间交付承诺，签约不确认收入 |
| scheduleDelivery | 按实际产成品成本出库，确认收入/COGS/应收；同批排15日后回款 |
| scheduleCollectReceivable | 逾期后可明确重试；已收拒绝再次收款 |
| schedulePayExpenseBill | 仅清偿已确认该期未付费用，不重复记费用 |

全部入口保留command内容幂等、创建线程、暂停拒绝和due>当前时点；已知后续耗时溢出提前拒绝。排程只返回SCHEDULED，实际结果从`snapshot().manufacturing().reports()`按taskId取得；报告为管理审计，包含原command、kind、业务ID、真实转移现金、模拟时点和提交位置。交付报告关联应收ID，不把尚未收款的收入写成现金事件。

新运行自带第0期强制关期任务，每次成功关期同批排下一期；没有任意关期/改账接口。到期取task.dueTime，不能以advance目标代替。内部任务/账单ID遇用户已用名称会选择空闲名称，不禁止用户前缀。真实资金事件独用MANUFACTURING_CASH_TRANSFERRED_V1载荷，明确fromAccountId/toAccountId/amount。

纯模型接收同一截止位置的账户表和可用现金，返回State/accounts候选，不自行写文件。假结果也可能包含失败/逾期元数据，必须提交该候选；业务钱股不足不会产生单边资产。Snapshot增加manufacturing组件，外部按位置new record的调用者需适配；旧存档的schema及已有访问器保持。构造非法参数抛异常，动态业务拒绝保存结果，I/O失败保留旧账和待办并暂停。预付/预收、债务、分红、外币、角色任职尚不在此接口能力中。

## 10. 治理管理契约

六参`WorldRuntime(file, manifest, openings, registry, ManufacturingRun.Config, BoardModel.Charter)`显式启用治理档案。章程公司必须对应制造发行组织，五席绑定五名不同登记人物，chair必须在席且quorum固定3；错误在创建文件前拒绝。旧档案省略governance字段，旧重载保持。

| 排程方法 | 到期语义 |
| --- | --- |
| scheduleBoardMeeting | chair召集BUDGET会议；绑定材料截止、开会、关会时点及到会/回避席位，同批排自动开会 |
| scheduleBoardMaterial | 到会且非回避席位在截止前提交唯一材料引用，不能替换原材料 |
| scheduleBudgetProposal | 提交各期间/类别的绝对新上限；不直接授权采购，不准追溯已关期间 |
| scheduleBoardVote | 每席一票；赞成/反对/弃权均保存，只允许表决窗口内投票 |
| scheduleBudgetImplementation | 已通过决议才可实施，明确成功一次；实施时再复核期间未关闭及cap不低于已花加未结承诺 |

自动开会在RULES阶段冻结材料；预算会议随后表决并自动关会，空提案到截止形成REJECTED/EMPTY_PROPOSAL终态。关会与同刻投票在COMPLETION的稳定排序可能令截止票返回INVALID_STATE或VOTING_CLOSED，两者都拒绝，不承诺原因码优先级。治理回报按taskId读取`BoardRun.Report`，包含commandId、kind、meetingId、accepted、reason、timeMillis与position；SCHEDULED仍只是待办受理。

`BoardRun.PeriodEvidence`固定period、capturedAt、position、复盘会议和原始来源引用、合同/应收ID及三项客观分值。经营兑现无到期合同为null；风险把到期时刻≤截止时刻且未收的AR计逾期。未实现的披露质量、长期投入始终列缺项，ReviewResult.total为null。raw Snapshot、会议材料引用及管理来源不能直接作为角色已读内容。

## 11. 任职及资料纯核契约

`RoleAccess.open(registry, openingAccounts, mandates)`只复制资产引用。`validateAgainst(registry, openingAccounts, state)`是可信加载校验，错误抛IAE；`appoint`/`revoke`返回不可变历史，`authorize`/`canReadPersonalAccount`对未知/无权返回统一NOT_AUTHORIZED。四岗任职只决定可调用能力，尚无角色下单/风险执行入口。

`InformationModel.open(registry, persons)`在开局一次登记读者。`publish`和`publishVersion`只追加原始版本；同文档发布者/受众固定。它们是受信管理操作，当前不校验编辑发布权，Runtime须对固定registry和组织受众补校验。

`catalog`仅给可见最新已发布版本的ID、版本、标题、公开发布者和时点；`startRead`固定版本并形成正耗时阅读，成功无正文；`completeRead`在now≥due时按due有效权限复核。COMPLETED/DENIED都在due终结，DENIED的false候选仍须保留释放工时。`cancelRead`严格在due之前，完成/取消/拒绝后重试不产生第二份经历。

`observations`只返回本人真实已完成版本；`canCite`要求本人该版本已在所查询时点完成。重读返回最早经历的readId，不新增同版本经历；运行桥必须以本次任务readId记录终态、以(person,docId,version)去重经历。序号倒退、未来完成及正文与版本不一致的JSON恢复被拒。原始State/Document/toJson为管理数据，不向角色直接开放。

## 12. 人物阅读运行契约

## 15. 决定纯核接口

`DecisionModel.open(runId,seed,config)`冻结配置，初始等待显式beginSession。所有转换返回不可变Result/State，不访问世界账或调用提供方。

| 接口 | 合同 |
| --- | --- |
| recover / beginSession | recover关闭接续标记而保留代次和历史，beginSession递增代次；已开放时拒绝重复开启 |
| openDecision | 固定人物、唤醒原因、准确输入、工具合同、观察截止及屏障，预留一次调用；同action同输入重放，异内容拒绝 |
| submitReply | 核对run/action/attempt/序号/代次，保存准确正文、usageSource与declaredUsage，严格解析外壳并结算一次 |
| failAttempt | 无回执技术失败按预留结算，保留原因并按预算和尝试上限重试 |
| resumeDecision | 可信宿主将旧代次未完成尝试保守结算，以当前代次保留原输入及屏障重试 |
| earliestBarrier | 查询仍OPEN决定的最早屏障，同刻复用WorldScheduler.fairOrder及actionId排序 |

技术失败保持TECHNICAL_FAILED，若预算阻止进一步重试，Result.reason为NO_RETRY_BUDGET且该原因持久保留于最后尝试。尚未发生任何调用的预算耗尽为零尝试BUDGET_EXHAUSTED。该接口尚未成为世界业务调用入口，运行桥接续前由可信程序持有State。

## 17. 管理端决定审计

`WorldRuntime.decisionAudits()`从已确认WorldJournal事件导出不可变List，包含运行和尝试完整身份、类别、真实批次位置、三处宿主墙钟、两段单调等待、正文摘要和准确声明。未知派发保持null。无回执失败与超时的接收时点、接收等待和声明用量保持缺失。读取与重开不补时间，不生成批次。

正常回执通过摘要关联原Attempt原文。异正文、声明用量或来源复用已消费身份时，REJECTED_IDENTITY_REUSE保存准确被拒原文。首次拒绝增加一审计批次，原宿主编号和完整Reply同时绑定，同一非法回执跨宿主重投去重。旧代次已归档身份的异回执沿此路径处理，保留第一归档且继续队列。drain对拒绝仍计0个已应用决定。

审计随原回执、失败、超时或旧归档批次提交，独立身份拒绝有明确自己的审计批次。提交前与恢复期核对真实位置、原请求、前后尝试状态及归档变化。字段只服务管理端，人物输入仍由原角色投影生成。附加事件沿原schema8契约，实际旧7/8兼容证据见运行记录第21节。

## 30. B2c1 完成登记接口

- `WorldRuntime.offerLiveDecisionCompletion(Completion)`：任意线程登记，不读取世界，返回QUEUED/DUPLICATE/UNKNOWN/CLOSED；调用者不能指定到达时点。Runtime不公开Inbox或claim绑定。
- `drainDecisionCallbacks()`与`expireDecisionTimeouts()`：live共用writer pump，前者返回处理总数，后者返回其中超时数；二者都可能处理已及时登记的回执。成功持久后settle，IOException/RuntimeException时retry全部尚未处理claim。
